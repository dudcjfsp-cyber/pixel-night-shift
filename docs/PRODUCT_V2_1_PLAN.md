# 《픽셀 야간근무》 Product V2.1 재미 검증 계획

## 1. 문서 상태

- 작성일: 2026-07-28
- 기준 브랜치: `codex/product-v2-implementation`
- 기준 커밋: `737dddf`
- 상태: 구현 준비가 끝난 V2.1 작업 권위 문서
- 선행 기준: [Product V2 계획표](PRODUCT_V2_PLAN.md)

V2.0은 `주간 정비 → 9+1웨이브 야간근무 → 근무 결과`의 기능 골격과 schema 3 저장을
완성했다. V2.1은 콘텐츠 수를 늘리기 전에 다음 질문을 검증한다.

> 플레이어가 위험을 미리 읽고, 주간에 고른 한 가지 개선이 다음 야간 결과를 바꿨다고
> 느끼며, 두 야간과 보스 국면을 서로 다른 문제로 받아들이는가?

이 문서는 기존 V2.0의 5초 일반 웨이브, 30초 보스, 3·6·10별, 완전 자동 전투와 주간
방치 메타를 바꾸지 않는다.

## 2. 확인된 현재 상태

### 구현 기준선

| 항목 | 현재 구현 |
|---|---|
| 기본 실행 | Product V2가 본편이며 `ProductLoopSession`이 제품 경계다. |
| 저장 | schema 3, `DAY_PREP/NIGHT_ACTIVE/SHIFT_RESULT` 원자 복원 |
| 야간 | 2초 준비, 일반 9웨이브, 1초 보스 경고, 30초 보스 |
| 주간 | 요원 강화, 패치 비교·교체, 보고서, 방치 수입, 버전 업데이트 |
| 콘텐츠 | 요원 4명, 패치 5개, 적 정의 3종, Watchdog 보스 1종, 야간 2회 |
| 외부 검증 | Product V2 외부 5인 테스트는 아직 실시하지 않음 |

2026-07-28 기준 `night_shift`, `day_meta`, `product_loop` 핵심 테스트는 각각 5/5,
총 15/15를 통과했다. 이 결과는 기능 경계와 결정론을 증명하지만 재미를 증명하지는 않는다.

### 지금 해결할 실제 간극

1. 첫째와 둘째 야간의 1~9웨이브 편성이 완전히 같다. 둘째는 체력 배율만 높아 별도의
   준비 전략이 잘 생기지 않는다.
2. `소형 오류`가 콘텐츠에 정의돼 있지만 실제 웨이브에는 한 번도 등장하지 않는다.
3. 주간의 요원 `DPS`는 기본 성장과 일반 패치 배율만 보여준다. 디버거의 낮은 직접 화력,
   빌드 엔지니어의 보스 배율, 스프라이트 장인의 팀 가속처럼 실제 역할 기여와 다르다.
4. 두 야간 모두 같은 Watchdog 이미지와 이름을 사용한다. 둘째의 12초 처리량 저하와
   강화된 특수 행동이 수치 차이로만 남아 있다.
5. 버전 업데이트 뒤에도 같은 두 야간이 반복되고 영구 성장 선택지는 한 단계뿐이다.
   현재 수직 슬라이스는 장기 진행을 제공하는 것처럼 보이지만 실제 콘텐츠는 그렇지 않다.
6. 정적 아이콘·배경은 결정론적 픽셀 생성기 결과지만, 활성 캐릭터 애니메이션과 오프닝
   배경에는 AI 원본을 격자화한 자산이 섞여 있어 수제 도트와 다른 인상을 줄 수 있다.

## 3. V2.1 고정 결정

### 유지

- 전투는 완전 자동으로 유지한다.
- 한 야간은 10웨이브, 일반 최대 5초, 보스 최대 30초를 유지한다.
- 버전당 야간 2회와 기존 요원·패치·적·보스 ID를 유지한다.
- 플레이어의 판단 시점은 주간 정비와 근무 결과로 유지한다.
- schema 3 저장 모양과 `AppRoot → ProductLoopSession → domain/content` 방향을 유지한다.

### 이번에 하지 않음

- 신규 요원, 패치, 적, 보스, 재화와 장비
- 수동 공격, 액티브 스킬, 실시간 패치 교체
- 세 번째 야간, 지역, 무한 웨이브와 버전별 신규 콘텐츠
- schema 4와 새 영구 저장 필드
- AI 생성 자산 전체 교체
- `main` 병합과 공개 배포 정책 변경

### 버전 업데이트의 정직한 표현

V2.1 외부 테스트는 **버전 1의 두 야간과 첫 버전 업데이트까지**를 한 회차로 평가한다.
버전 2부터는 같은 콘텐츠가 반복되는 테스트 구간임을 화면과 테스트 안내에 명시한다.
장기 버전 성장, 무한 난이도와 추가 영구 선택지는 V2.1 결과를 본 뒤 별도 마일스톤으로
결정한다.

## 4. 제품 변경안

### 야간 1: 침입 규칙 학습

- `소형 오류`를 초반 다수 편성에 실제 사용한다.
- `일반 오류`와 섞어 적 수와 침입 피해가 서로 다른 값이라는 점을 학습시킨다.
- 첫 별 전에는 단순 편성, 첫 별 뒤에는 소형 다수와 일반 혼합을 사용한다.
- 다음 웨이브 안내는 적 이름뿐 아니라 `개체 수 · 최대 침입 피해`를 쉬운 말로 보여준다.

목표는 첫째 야간이 `적을 놓치면 안정도가 줄어든다`는 규칙을 가르치는 것이다.

### 야간 2: 우선순위와 보스 압박

- 초반부터 `일반 오류 + 급증 오류` 혼합을 사용한다.
- 급증 오류가 포함된 웨이브는 적색 경고와 예상 최대 침입 피해를 먼저 보여준다.
- 같은 총 HP 배율만 올리지 않고 기존 세 적의 수와 조합으로 파형을 구분한다.
- 보스 전에는 `12초 뒤 처리량 저하`를 카운트다운하고 발동 뒤 상태명을 계속 표시한다.

목표는 둘째 야간이 `어떤 위험을 먼저 대비할지` 묻는 근무로 읽히게 하는 것이다.

### 주간 선택의 사실성

요원 상세의 단일 `DPS`를 실제 역할 전체를 뜻하는 것처럼 표시하지 않는다.

- 현재 수치는 `기본 화력`으로 명확히 이름 붙인다.
- 강화 전후를 기존 결정론적 `ProductV2Forecast`로 각각 실행한다.
- 다음 근무 기준으로 다음 네 값을 함께 보여준다.
  - 예상 완료 웨이브
  - 예상 침입 피해
  - 예상 보스 결과 또는 남은 HP
  - 반복 근무 급여
- 디버거는 생존, 빌드 엔지니어는 보스, 스프라이트 장인은 팀 템포, QA 임프는 구조
  변화가 드러나야 한다.

예측은 설명용 별도 공식으로 흉내 내지 않고 실제 야간 시뮬레이터를 사용한다.

### Watchdog 두 국면

새 보스를 추가하지 않고 기존 프로필을 두 운영 모드로 구분한다.

| 근무 | 화면상의 국면 | 강조할 기존 행동 |
|---|---|---|
| 첫째 야간 | `복구 감시 모드` | 전열 공격, ROLLBACK 회복 |
| 둘째 야간 | `처리량 제한 모드` | 강한 특수 행동, 12초 처리량 저하, 빠른 ROLLBACK |

행동 경고, 상태명, 색상과 효과음은 달라지되 도메인 판정 순서와 저장 필드는 추가하지 않는다.

## 5. 실제 도트 파일럿

현재 자산을 전부 교체하기 전에 AI 원본 또는 sprite-gen 파생물이 실제 화면 인상에
영향을 주는 다음 표본만 비활성 비교본으로 만든다. `watchdog_process`와
`battle_server_room`은 이미 생성기가 한 픽셀씩 결정론적으로 그리는 자산이므로
`가짜 도트 교정` 표본에서 제외한다.

| 분류 | 파일럿 | 이유 |
|---|---|---|
| 요원 | `debugger` 32×32, `idle/upgrade` | 활성 sprite-gen 파생물과 수제 실루엣·작은 장비 표현 비교 |
| 적 | `broken_pixel` 32×32, `idle/hurt` | 활성 sprite-gen 파생물과 수제 불규칙 형태·피격 읽기 비교 |
| 환경 | `title_background`의 96×64 대표 구간 | AI 원본 축소·16색 양자화와 직접 찍은 배경 밀도 비교 |
| 글자 | 비회전 11px 한글 UI 표본 | Galmuri TTF 안티앨리어싱과 비트맵 대안의 실제 가독성 비교 |

래스터 파일럿은 한 칸씩 수정 가능한 원본 격자에서 제작하고 생성형 이미지의 축소본을
새 기준으로 사용하지 않는다. `debugger`와 `broken_pixel` 비교본은 sprite-gen run이
아닌 수동 제작물이다. `game/assets/pilots/manual_pixel/` 아래에 격리하고 기존
`game/assets/generated/` 파일, sprite run manifest와 해시를 덮어쓰지 않는다.
애니메이션은 화려함보다 적은 프레임의 정확한 픽셀 이동을 우선한다.

### 파일럿 통과 기준

- 래스터 원본 크기와 한 픽셀 격자가 정확하다.
- 래스터는 반투명 가장자리 없이 알파 0 또는 255만 사용한다.
- 캐릭터·적은 투명색 포함 12색 이하, 배경은 16색 이하이다.
- 파일럿 전용 최소 검증기가 크기·팔레트·알파를 확인한다.
- 접촉 시트의 1×·2×·3× 정수 확대에서 `Nearest`로 비교한다. 다양한 Galaxy 화면을
  채우는 전체 Web 캔버스까지 정수 배율로 강제하지 않는다.
- 글자 표본은 같은 문구·크기에서 잘린 자모 없이 TTF 안티앨리어싱 켜짐·꺼짐과
  비트맵 대안을 나란히 비교한다.
- 360×640에서 기존 자산보다 실루엣과 피격 상태를 덜 혼동한다.
- 비교 참가자 5명 중 3명 이상이 파일럿을 더 일관되거나 읽기 쉽다고 고른다.
- 승인 전에는 `game/assets/manifest.json`의 활성 매핑을 바꾸지 않는다.

## 6. 1~7단계 실행표

| 단계 | 작업 | 완료 기준 | 커밋 경계 |
|---|---|---|---|
| 1. 권위 문서·기준선 | V1 목표로 남은 문서를 현재 V2/schema 3 현실과 동기화하고 실제 콘텐츠 기준선 보고서를 만든다. | 문서가 Product V2를 현재 본편으로 일관되게 부르고 핵심 15개 테스트가 통과한다. | 문서 / 기준선 보고 분리 |
| 2. 사실 기반 강화 예측·버전 안내 | 요원 강화 전후를 실제 `ProductV2Forecast`로 비교하고 단일 DPS 표현을 정리한다. 첫 업데이트 확인창과 버전 2 주간 화면에는 반복 테스트 구간임을 명시한다. | 네 역할 중 하나를 강화했을 때 다음 근무 변화가 같은 화면에 보이고 실제 결과 방향과 일치한다. 업데이트 전후 모두 장기 신규 콘텐츠로 오해할 문구가 없다. | 도메인 예측 / 주간 UI·버전 문구 분리 |
| 3. 두 야간 편성 분리 | 승인된 미리보기 저장 격리를 먼저 연결한 뒤 기존 적 3종만으로 첫째 학습형, 둘째 혼합 위험형 웨이브를 구성한다. | 미리보기가 기존 본편 저장을 읽거나 지우지 않고, `소형 오류`가 실제 등장하며 두 근무의 1~9웨이브 편성이 같지 않고 5초 규칙은 유지된다. | 저장 격리 / 콘텐츠 / 표시 경고 분리 |
| 4. Watchdog 국면 차별화 | 기존 행동을 이용해 복구 감시와 처리량 제한 모드를 텔레그래프한다. | 처음 보는 플레이어가 두 번째 보스의 12초 위험과 실패 원인을 설명한다. | 상태 파생값 / 연출·오디오 분리 |
| 5. 실제 도트 파일럿 | 수동 캐릭터·적, 오프닝 배경 구간과 한글 표본의 비활성 비교 자산·접촉 시트를 만든다. | 파일럿 전용 크기·팔레트·알파 검증 통과, 활성 매핑은 유지된다. | 파일럿 생성 / QA 자료 분리 |
| 6. 통합 재미 점검 | 실제 기본 콘텐츠로 무강화·역할 집중·균등 강화 경로를 비교하고 PC·Galaxy 수동 E2E를 수행한다. | 아래 목표 범위를 만족하는 자연 진행 경로가 있고 저장·UI 회귀가 없다. | 밸런스 / 통합 폴리시 분리 |
| 7. 외부 5인 관문 | 새 저장의 자연 진행으로 버전 1 두 야간과 첫 업데이트까지 외부 테스트를 실시한다. | 아래 수용 기준을 만족하고, 결과가 없는 항목을 통과로 기록하지 않는다. | 테스트 기록 / 확정 수정 분리 |

테스트는 새 UI 문구마다 만들지 않는다. 실제 시뮬레이터를 사용하는 강화 예측 경계와
웨이브 콘텐츠 검증만 자동화하고, 이해도·속도감·도트 인상은 수동 테스트로 판정한다.

### 밸런스 경로 목표

| 경로 | 목표 |
|---|---|
| 무강화 대조군 | 급여를 받고 소프트락 없이 다음 정비가 가능하되 둘째 야간 ★★★는 목표로 하지 않는다. |
| 균등 강화 | 정상 보상만 사용해 첫째·둘째 야간에서 최소 ★★에 도달한다. |
| 증거 기반 역할 집중 | 예측이 가리킨 병목을 강화해 해당 지표가 실제로 개선되고, 각 야간을 늦어도 두 번째 시도에 ★★★로 마친다. |

외부 테스트의 1차 경로는 준비된 저장 없이 `TITLE → 버전 1 두 야간 → 첫 업데이트`를
자연 진행한다. 한 야간을 두 번 시도해도 다음 단계에 도달하지 못하면 진행성 실패로
기록한다. 이후 둘째 보스 이해도만 별도로 보기 위해 준비된 저장을 제공할 수 있지만,
그 결과는 자연 진행 성공률과 섞지 않는다.

## 7. 수용 기준

- 5명 중 4명 이상이 지킬 대상, 종료 이유와 다음 주간 행동을 설명한다.
- 5명 중 4명 이상이 일반 HP와 제한시간을 혼동하지 않는다.
- 5명 중 3명 이상이 선택한 강화 또는 패치가 다음 결과를 어떻게 바꿀지 미리 말한다.
- 5명 중 3명 이상이 첫째와 둘째 야간의 위험 차이를 설명한다.
- 5명 중 3명 이상이 실제 도트 파일럿을 기존 비교본보다 일관되거나 읽기 쉽다고 고른다.
- 5명 모두 업데이트 확인 전 `버전 2부터 같은 두 야간이 반복되는 테스트 구간`임을
  확인할 수 있고, 업데이트 후 주간에도 같은 사실이 표시된다.
- 5명 중 3명 이상이 여전히 `야간에 할 일이 없다`고 답할 때만 웨이브 5 뒤 1회 관제
  지시안을 별도 A/B 안건으로 연다.
- 같은 입력과 경과시간은 변경 뒤에도 같은 전투 결과를 만든다.
- 기존 schema 3 저장 모양, 원자 복원과 중복 보상 방지는 유지된다.

## 8. 구조와 저장 게이트

설계 게이트는 `PASS`다. 3단계의 저장 호환성 결정도 2026-07-28에 아래와 같이
확정됐다.

- 새 V2 기능은 legacy `GameSession`이 아니라 `ProductLoopSession`에 연결한다.
- 전투 수치와 편성은 `game/content/product_v2/`가 소유한다.
- 전투 결과와 사건은 `NightShiftSimulator`가 소유한다.
- 강화·패치 예측은 `ProductV2Forecast`가 실제 시뮬레이터를 호출해 만든다.
- 표시 계층은 스냅숏을 읽을 뿐 도메인 상태를 직접 바꾸지 않는다.
- `AppRoot`에는 새 게임 규칙을 넣지 않고 기존 전환·tick·저장 역할만 유지한다.

V2.1은 새 지속 상태를 추가하지 않고 schema 3를 유지하는 것이 기본안이다. 그러나
`NIGHT_ACTIVE` 저장은 현재 웨이브의 런타임만 보존하고 남은 웨이브 표나 콘텐츠 revision을
저장하지 않는다. V2.0 편성으로 시작한 저장을 V2.1에서 열면 현재 웨이브는 옛 편성,
다음 웨이브는 새 편성으로 이어질 수 있다. 따라서 3단계 전에 다음 중 하나를 명시적으로
결정해야 하며, 조용한 초기화는 금지한다. Git 브랜치만 나누어도 같은 앱 이름과
`user://pixel_night_shift`를 사용하므로 저장 공간은 자동으로 격리되지 않는다.

**승인된 방식:** V2.1 미리보기 빌드는
`user://pixel_night_shift_v2_1_preview`를 사용해 새 기록으로 시작한다. 기존 본편 경로
`user://pixel_night_shift`는 읽거나 지우지 않는다. 미리보기 export feature 또는
조립 시점의 `SaveRepository` 주입으로 경로를 선택하며, schema 3 DTO와 본편 기본 경로는
바꾸지 않는다.

schema 4 `content_revision` 이관은 선택하지 않았다. 보스 최대 HP, 제한시간, 안정도
상한과 DTO 키 변경이 추가로 필요해지면 이 결정을 재사용하지 않고 별도 게이트로
돌아온다.

## 9. 다음 결정 관문

저장 호환성 결정은 위 전용 미리보기 공간으로 해결됐다. 앞으로 사용자 결정이 반드시
필요한 지점은 다음 두 가지다.

1. 7단계 전에 `main`을 건드리지 않는 별도 V2 미리보기 배포를 승인한다.
2. 외부 테스트 뒤 장기 버전 성장과 신규 콘텐츠를 V2.2로 열지, 현재 수직 슬라이스의
   완성도만 더 높일지 선택한다.

새 보스·적·수동 야간 입력은 외부 결과 전에는 구현하지 않는다. `main`은 현재 지시대로
병합 대상에서 제외한다.
