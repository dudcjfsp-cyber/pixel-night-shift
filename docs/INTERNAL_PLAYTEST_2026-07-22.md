# 2026-07-22 내부 1회차 플레이테스트

## 범위와 방법

- Godot `4.7.stable.official.5b4e0cb0f`, Windows, 논리 해상도 360×640
- 기본 본편 `GameSession` 사용. Combat V2 테스트 모드는 사용하지 않음
- 첫 근무부터 스테이지 20, 버전 업데이트 승인, 2회차 시작까지 연속 실행
- 실제 화면 버튼 명령으로 60초마다 패치·강화를 선택했으며 도메인 상태를 직접 변경하거나 시간을 가속하지 않음
- 저장 경로와 로그는 `.godot/manual-playtest/` 아래에 격리

## 결과

- 판정: 통과
- 스테이지 20 완료 및 버전 업데이트 준비: 1,229.1초(20분 29.1초)
- 버전 업데이트 승인과 2회차 요약 완료: 1,229.4초
- 화면을 통한 운영 결정: 19회
- 스테이지 10: 제한시간 실패 1회, 두 번째 시도에서 10.93초에 클리어
- 스테이지 20: 제한시간 실패 3회, 여섯 번째 전체 보스 시도에서 17.31초에 클리어
- PROCESS DOWN: 12회
- QA 자동 구조 성공: 4회
- 버전 업데이트 뒤 `run_count == 1`, 스테이지 1과 초기 자원으로 원자적으로 전환

실패·DOWN·구조 횟수는 버전 업데이트 뒤 초기화된 최종 스냅숏이 아니라, 주행 중 수집한 보스 이벤트 130건에서 계산했습니다.

## 화면·흐름 확인

- 첫 근무, 온보딩, 일반전, 보스 경고와 제한시간, 유지보수, 진단 카드와 사실 기반 어필, 패치 보드, 버전 업데이트 확인·요약을 모두 확인했습니다.
- 보스 실패 뒤 진행이 삭제되지 않고 유지보수 파밍과 자동 재도전으로 이어졌습니다.
- 스테이지 10과 20에서 요원 DOWN, QA 구조 예약·성공, 보스 회복과 디버프가 실제 이벤트에 맞게 표시됐습니다.
- 버전 업데이트 전 초기화·유지 항목과 패치노트 +1이 확인 화면 및 완료 요약과 일치했습니다.

## 발견 사항과 조치

- 차단 문제 1건: 첫 패치 장착 피드백이 패치 행동 영역과 겹쳤습니다. 패치 후보·미리보기의 최소 높이와 세로 간격을 줄이되 후보 버튼의 48px 터치 높이는 유지했습니다. 같은 저장 상태를 다시 연 360×640 캡처에서 피드백, 버튼, 설명이 겹치지 않는 것을 확인했습니다.
- 비차단 관찰 1건: 전투 레인 안의 작은 `PROCESS DOWN` 글자는 일부 상황에서 읽기 어렵습니다. 진단 카드와 QA 상태띠가 같은 사실을 명확히 보완하므로 이번 내부 관문은 통과시키고 5인 플레이테스트 관찰 항목으로 남깁니다.
- 스테이지 20 최초 진입 캡처는 상태 전환 직후 한 프레임 빨리 저장되어 보스 화면 증거에서 제외했습니다. 실제 보스 이벤트와 최종 완료 화면은 정상입니다.

## 결론

기본 본편은 360×640 한 회차 완료 관문을 통과했습니다. 다음 제품 관문은 `docs/PLAYTEST.md` 기준 5인 플레이테스트이며, Android 패키징과 실기기 확인은 사용자 결정에 따라 계속 보류합니다.
