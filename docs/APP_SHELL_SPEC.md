# 앱 셸·야간 운영실 화면 명세

## 문서 상태

- 상태: 구현 승인 전 와이어프레임 기준안
- 대상 마일스톤: 앱 셸, 로컬 저장, 복귀 흐름
- 기준 해상도: 세로 `360×640`
- 기존 20스테이지 전투·진단·패치 규칙은 변경하지 않습니다.

이 문서는 앱 실행부터 현장 진입, 복귀, 설정, 버전 업데이트, 저장 오류까지의 화면과 상태를 한곳에서 정의합니다. `야간 운영실`은 빈 메인 메뉴가 아니라 현재 회차의 상황을 요약하고 현장으로 돌아가는 기능형 허브입니다.

## 제품 결정

1. 첫 실행은 한 번의 `첫 근무 시작` 뒤 기존 현장에서 플레이형 온보딩을 시작합니다.
2. 정상적인 완전 재실행은 `야간 운영실`로 들어갑니다. 의미 있는 부재 결과가 있으면 그 위에 `야간 인수인계`를 한 번 표시합니다.
3. 짧은 앱 전환은 스플래시, 운영실, 복귀 팝업 없이 마지막 화면과 탭을 그대로 복원합니다.
4. 운영실이나 설정을 보고 있는 동안 활성 회차의 자동 전투는 계속됩니다.
5. 앱이 백그라운드에 들어가면 실시간 전투를 중단하고, 복귀할 때 저장된 시각을 기준으로 결정론적으로 집계합니다.
6. 오프라인 진행은 현재 요원과 패치 구성만 사용합니다. 패치 선택이나 버전 업데이트를 대신 수행하지 않습니다.
7. 복귀 결과는 먼저 세션에 적용하고 저장한 뒤 읽기 전용 보고서로 보여줍니다. 보고서를 다시 열어도 보상이 중복 지급되지 않습니다.
8. 진행 저장과 사용자 설정은 분리합니다. 근무 기록을 초기화해도 소리와 접근성 설정은 유지합니다.
9. 광고, 상점, 출석, 우편함, 계정, 클라우드 저장, 라이브 이벤트는 이 마일스톤에 넣지 않습니다.

## 용어

| 피할 표현 | 사용할 표현 |
|---|---|
| 대기실·로비 | 야간 운영실 |
| 저장 파일 | 근무 기록 |
| 오프라인 보상 | 야간 인수인계·자동 운영 결과 |
| 게임 화면 | 현장 |
| 환생·prestige | 버전 업데이트 |
| 보상 받기 | 현장 복귀·정체 지점 확인 |
| 새 게임 | 첫 근무·새 근무 시작 |

기존 용어인 `야간근무 N회차`, `자동 운영`, `비트`, `패치노트`, `병목`, `진단`, `유지보수`, `감시견 프로세스`는 유지합니다.

## 화면 구조

### 최상위 화면

동시에 하나만 존재합니다.

```text
BOOT
FIRST_START
OPERATIONS_ROOM
GAMEPLAY
SAVE_RECOVERY
```

### 오버레이

최상위 화면 위에 동시에 하나만 엽니다.

```text
NONE
OFFLINE_REPORT
SETTINGS
VERSION_UPDATE_CONFIRM
RUN_SUMMARY
ONBOARDING
```

오버레이 위에 또 다른 오버레이를 쌓지 않습니다. 파괴적 확인이 필요하면 현재 오버레이의 내용을 확인 상태로 바꿉니다.

## 실행 경로

```text
첫 설치
시스템 스플래시 → BOOT → FIRST_START → GAMEPLAY + ONBOARDING

정상 완전 재실행, 변화 없음
시스템 스플래시 → BOOT → OPERATIONS_ROOM → GAMEPLAY

정상 완전 재실행, 변화 있음
시스템 스플래시 → BOOT → OPERATIONS_ROOM + OFFLINE_REPORT → GAMEPLAY

짧은 앱 전환
마지막 최상위 화면과 오버레이 없는 상태로 즉시 복원

저장 이상
시스템 스플래시 → BOOT → SAVE_RECOVERY

버전 업데이트
GAMEPLAY + VERSION_UPDATE_CONFIRM → 저장 성공 → RUN_SUMMARY → GAMEPLAY
```

Android 시스템 스플래시 뒤 로컬 복원이 `300ms` 안에 끝나면 별도 부트 문구를 그리지 않습니다. 더 길어질 때만 `근무 기록 확인 중…`을 표시하며 가짜 진행률은 사용하지 않습니다.

## 기능 와이어프레임

아래 배치는 실제 `360×640` 화면 안의 정보 우선순위를 정의합니다. 장식용 픽셀 아트는 와이어프레임 승인 뒤 추가합니다.

### 1. 첫 근무 시작

```text
┌──────────────────────────────────┐
│ PIXEL NIGHT SHIFT          [설정] │ 52
│                                  │
│          [요원·서버실 삽화]       │
│                                  │
│          픽셀 야간근무            │
│ 서비스 종료 전까지, 이 세계는     │
│ 멈추지 않습니다.                  │
│                                  │
│ 전투는 요원들이 맡습니다.          │
│ 병목을 진단하고 패치를 선택하세요. │
│                                  │
│        [ 첫 근무 시작 ]           │ 52
└──────────────────────────────────┘
```

- 최초 한 번만 표시합니다.
- 설정 버튼의 터치 영역은 `48×48` 이상입니다.
- `첫 근무 시작` 직후 새 세션을 만들고 최초 저장에 성공한 다음 현장으로 전환합니다.
- 최초 저장 실패 시 현장 진입 전에 오류를 명확히 알립니다.

### 2. 야간 운영실

```text
┌──────────────────────────────────┐
│ 야간 운영실              [설정]  │ 52
│ 야간근무 2회차 · 자동 운영 중     │
│                                  │
│       [운영실 상태 삽화]           │ 192~224
│                                  │
│ 현재 현장        STAGE 14         │
│ 주요 병목        처리량 부족       │
│ 장착 패치        2 / 3            │
│ 다음 목표        감시견 · ST 20    │
│                                  │
│ 방금 저장됨                       │
│        [ 현장 복귀 ]              │ 52
│ [운영 매뉴얼]          [설정]      │ 48
└──────────────────────────────────┘
```

- 운영실은 상태 요약과 진입만 담당합니다.
- 요원 강화와 패치 교체를 운영실에 복제하지 않습니다.
- `현장 복귀`는 유일한 주 행동입니다.
- 저장 실패 중에는 `저장되지 않음`을 위험 상태로 계속 표시합니다.

### 3. 야간 인수인계

운영실 위 최대 `328px` 폭의 모달입니다.

```text
┌──────────────────────────────┐
│ 야간 인수인계                 │
│ 2시간 14분 동안의 자동 운영   │
│ 결과입니다.                   │
│                              │
│ 회수한 비트       +12.4K      │
│ 진행             ST 14 → 17  │
│ 정체 지점         STAGE 17    │
│ 정체 원인         예상 처치가 │
│                  4.8초 느림   │
│                              │
│ 결과는 근무 기록에 이미       │
│ 반영되었습니다.                │
│ [ 정체 지점 확인 ]             │
│ [ 운영실 보기 ]                │
└──────────────────────────────┘
```

- 병목이 없으면 주 버튼은 `현장 복귀`입니다.
- 집계 상한에 닿으면 `8시간 이후의 결과는 집계되지 않았습니다.`를 덧붙입니다.
- 실제 변화가 없으면 표시하지 않습니다.
- 보고서를 닫는 행동은 보상 지급 행동이 아닙니다.

초기 보고서 표시 정책은 다음과 같습니다.

```text
표시 = 가시적인 진행 변화가 있고 다음 중 하나를 만족
  - 부재 시간 120초 이상
  - 스테이지가 바뀜
  - 보스·유지보수·완료 상태가 바뀜
  - 8시간 집계 상한에 닿음
```

`120초`와 `8시간`은 플레이테스트 가능한 앱 정책 값이며 도메인 규칙에 하드코딩하지 않습니다.

### 4. 현장

현재 구현된 게임 화면을 유지합니다. 변경점은 다음에 한정합니다.

- `MainView`가 세션과 오디오를 직접 생성하지 않고 앱 셸로부터 전달받습니다.
- `MainView`가 전투 시간을 직접 진행하지 않습니다.
- 헤더의 음악·효과음 토글은 하나의 `설정` 진입점으로 정리합니다.
- `버전 업데이트` 버튼은 즉시 초기화하지 않고 확인 오버레이를 요청합니다.
- 현장에서 운영실로 나가도 같은 세션과 활성 탭을 유지합니다.

### 5. 설정

```text
┌──────────────────────────────┐
│ 설정                    [닫기] │
│                              │
│ 배경음악 음량          80%    │ 48+
│ 효과음 음량            70%    │ 48+
│ 진동 피드백            켬     │ 48+
│ 화면 흔들림            켬     │ 48+
│ 점멸 효과              줄임    │ 48+
│ 동작 줄이기            끔     │ 48+
│ 화면 전환과 반복 애니메이션을  │
│ 줄입니다.                     │
│                              │
│ 저장 상태              정상   │
│ [저장 다시 시도]               │
│                              │
│ [운영 매뉴얼 다시 보기]         │
│ [근무 기록 초기화…]             │
└──────────────────────────────┘
```

- 소리와 접근성 설정은 변경 즉시 적용하고 별도 설정 파일에 저장합니다.
- 지원하지 않는 플랫폼의 진동은 비활성 상태와 이유를 표시합니다.
- `근무 기록 초기화…`는 즉시 실행하지 않습니다.

초기화 확인 문구:

> **근무 기록을 초기화할까요?**
>
> 현재 회차, 패치노트, 발견 기록과 영구 강화가 삭제됩니다. 이 작업은 되돌릴 수 없습니다. 소리와 접근성 설정은 유지됩니다.

버튼은 `취소`, `모든 기록 삭제`입니다.

### 6. 버전 업데이트 승인

```text
┌──────────────────────────────┐
│ 버전 업데이트 승인            │
│ 현재 회차를 정리하고 다음      │
│ 야간근무를 시작합니다.          │
│                              │
│ [초기화됩니다]  [유지됩니다]    │
│ STAGE 진행      패치노트        │
│ 비트            발견 기록      │
│ 요원 레벨       열린 슬롯       │
│ 장착 패치       레거시 캐시     │
│                              │
│ 이번 보상 · 패치노트 +1         │
│ [ 업데이트 실행 ]              │
│ [ 조금 더 운영 ]               │
└──────────────────────────────┘
```

- 초기화 항목과 유지 항목을 색만으로 구분하지 않고 제목과 목록으로 함께 표시합니다.
- `업데이트 실행`은 성공한 한 번의 세션 변경과 저장으로 처리합니다.
- 저장 실패 시 완료 보고서를 열지 않으며, 반쪽짜리 새 회차를 만들지 않습니다.

### 7. 버전 업데이트 완료

```text
┌──────────────────────────────┐
│ 버전 업데이트 완료            │
│                              │
│ 야간근무 2회차가 시작되었습니다.│
│ 패치노트 +1                  │
│                              │
│ 이전 회차 최고 STAGE    20    │
│ 가장 오래된 병목      복구 과다 │
│ 사용한 패치            3개    │
│                              │
│ 다음 목표 · 첫 보스 도달 시간  │
│ 이전 회차보다 25% 단축         │
│                              │
│ [ 새 회차 시작 ]              │
└──────────────────────────────┘
```

- 이전 회차 요약은 업데이트 실행 직전 스냅숏에서 만들고, 성공한 저장 뒤 읽기 전용으로 보여줍니다.
- 보고서를 보지 못하고 앱이 종료되어도 새 회차 저장의 일관성이 우선입니다.

### 8. 저장 복구

```text
┌──────────────────────────────┐
│ [오류] 근무 기록에 문제가     │
│ 있습니다.                    │
│                              │
│ 가장 최근 기록을 읽을 수      │
│ 없습니다. 이전 백업은 사용할  │
│ 수 있습니다.                 │
│                              │
│ 복구 시점 · 2026.07.11 14:32 │
│ 일부 최근 진행은 반영되지     │
│ 않을 수 있습니다.             │
│                              │
│ [ 백업으로 복구 ]             │
│ [ 다시 시도 ]                 │
│                              │
│ [ 새 근무 시작… ]             │
└──────────────────────────────┘
```

- 백업도 손상되었다면 `현재 기록과 백업을 모두 읽을 수 없습니다.`라고 명시합니다.
- 더 새로운 저장 스키마라면 손상으로 취급하지 않고 `게임 업데이트가 필요합니다.`를 표시합니다.
- `새 근무 시작…`은 별도의 파괴적 확인 전에는 기록을 삭제하지 않습니다.
- 저장 오류를 기본값으로 조용히 대체하지 않습니다.

### 9. 플레이형 온보딩

별도 설명 슬라이드를 만들지 않고 기존 현장 위에서 세 단계로 진행합니다.

1. **전투는 요원들이 맡습니다.** `먼저 지켜보세요. 반복해서 누를 필요는 없습니다.` 버튼: `확인`
2. **병목이 감지되었습니다.** `진단 카드에서 느려진 원인을 확인하세요.` 버튼: `진단 보기`
3. **대응 방법은 하나가 아닙니다.** `요원을 강화하거나, 장점과 부작용이 있는 패치를 선택하세요.` 버튼: `직접 판단하기`

설명 카드는 강조 대상을 가리지 않도록 화면 위·아래를 바꾸며 배치합니다. 언제든 건너뛸 수 있고 설정에서 다시 볼 수 있습니다.

## 상태와 예외 처리

| 조건 | 표시 | 자동 운영 | 처리 원칙 |
|---|---|---:|---|
| 근무 기록 없음 | 첫 근무 시작 | 정지 | 버튼 뒤 새 세션 생성·최초 저장 |
| 정상 완전 재실행, 변화 없음 | 야간 운영실 | 재개 | 인수인계 생략 |
| 정상 완전 재실행, 변화 있음 | 운영실 위 인수인계 | 재개 | 결과 적용과 저장을 먼저 완료 |
| 짧은 앱 전환 | 마지막 화면·탭 | 계속 | 팝업과 토스트 없음 |
| 긴 앱 전환 | 필요한 경우 인수인계 | 재개 | 같은 결과를 두 번 적용하지 않음 |
| 백그라운드에서 프로세스 종료 | 완전 재실행과 동일 | 집계 후 재개 | 진행 저장을 화면 상태보다 우선 |
| 기기 시간이 과거로 이동 | 필요 시 안내 | 경과 `0초` | 음수 진행 금지 |
| 시간이 크게 미래로 이동 | 상한 안내 | `8시간`까지만 | 앱 정책 상한 적용 |
| 업데이트 잠김 | 비활성 버튼 | 계속 | 확인창을 열지 않음 |
| 업데이트 확인 취소 | 기존 현장 | 계속 | 세션 변경 없음 |
| 업데이트 실행 성공 | 완료 보고서 | 새 회차 | 원자적 변경 뒤 즉시 저장 |
| 업데이트 중 앱 종료 | 이전 또는 새 회차 | 해당 상태 | 반쪽짜리 회차 로드 금지 |
| 설정 변경 | 현재 화면 유지 | 계속 | 즉시 적용·별도 저장 |
| 주 저장 손상·백업 정상 | 복구 화면 | 정지 | 알림 없이 되돌리지 않음 |
| 주 저장·백업 모두 손상 | 복구 실패 | 정지 | 명시적 확인 전 삭제 금지 |
| 저장 쓰기 실패 | 지속 경고 | 계속 가능 | 성공 전까지 정상 저장처럼 표시하지 않음 |

## 뒤로가기

```text
오버레이 열림       → 오버레이 닫기
설정·하위 화면      → 이전 화면
현장                → 야간 운영실
야간 운영실         → 시스템에 앱 이탈 요청
첫 근무·복구 화면   → 시스템에 앱 이탈 요청
```

자동 저장되는 일반 이탈에는 종료 확인창을 띄우지 않습니다. 근무 기록 삭제처럼 되돌릴 수 없는 행동에만 확인을 사용합니다.

### 치수

- 실제 안전 영역 안에 다시 좌우 `8px` 콘텐츠 여백을 둡니다.
- 주요 버튼 높이는 `52px`, 모든 터치 영역은 최소 `48×48px`입니다.
- 설명 화면 본문은 `11~12px`, 보조문은 최소 `10px`, 제목은 `15~20px`입니다.
- 패널 간격은 현장 `4px`, 운영실·설명 화면 `8~12px`입니다.
- 기본 테두리 `1px`, 선택·위험 강조 `2px`, 모서리 `4px`를 사용합니다.
- 화면이 짧으면 글자를 줄이는 대신 세로 스크롤을 허용합니다.
- 중요한 상태는 색, 아이콘, 텍스트 표지를 함께 사용합니다.

### 에셋 재사용

- 운영실 현황: `bit`, `patch_note`, `stage`, `diagnosis`
- 현장 복귀: `combat`
- 야간 인수인계: `maintenance`, 보스 정체 시 `boss`
- 업데이트 완료: `complete`
- 첫 화면: 네 요원과 기존 서버실 띠를 임시 조합

`battle_server_room.png`는 `344×64` 전투 띠이므로 운영실 전체 배경으로 확대하지 않습니다. 운영실 전용 배경과 설정·저장·인수인계 아이콘은 와이어프레임 확인 뒤 생성기, 매니페스트, 검증기를 함께 확장합니다.

## 구현 계약

```text
AppRoot
 ├─ GameSession 1개
 ├─ AudioDirector 1개
 ├─ SaveRepository
 ├─ ScreenHost: 최상위 화면 1개
 └─ OverlayHost: 오버레이 최대 1개
```

- `AppRoot`만 화면 전환, `GameSession.tick()`, 저장·복귀 시점, 오디오 생명주기를 관리합니다.
- 각 화면은 다른 화면을 직접 열지 않고 `continue_requested`, `settings_requested`, `prestige_requested` 같은 의미 신호만 보냅니다.
- `MainView.configure(session, audio_director)`를 트리에 추가하기 전에 한 번 호출합니다.
- `MainView` 내부의 세션·오디오 생성과 전투 `tick()`은 제거합니다.
- 운영실·설정 중에는 `AppRoot`가 전투를 계속 진행합니다.
- 백그라운드에서는 실시간 `tick()`을 멈춥니다.
- 전역 이벤트 버스와 여러 Autoload를 추가하지 않습니다.

### 저장 경계

```text
game/persistence/save_repository.gd
game/persistence/save_load_result.gd
```

`SaveRepository`는 파일과 저장 봉투만 책임지고, 세션 데이터는 불투명한 `Dictionary`로 취급합니다.

```gdscript
SaveRepository.load() -> SaveLoadResult
SaveRepository.save(
    session_data: Dictionary,
    saved_at_unix: int,
    last_gameplay_tab: int
) -> Error

GameSession.export_state() -> Dictionary
GameSession.restore_state(data: Dictionary) -> PackedStringArray
```

- `snapshot()`은 화면 DTO이며 저장 데이터로 사용하지 않습니다.
- `export_state()`는 저장 전용 DTO입니다.
- 복원은 새 상태 후보를 전부 검증한 뒤 한 번에 교체합니다.
- 복원 실패는 현재 세션을 변경하지 않습니다.
- 누락 키, 비정상 숫자, 알 수 없는 콘텐츠 ID를 조용한 기본값으로 바꾸지 않습니다.

저장 봉투의 최초 형태:

```json
{
  "schema_version": 1,
  "saved_at_unix": 0,
  "last_gameplay_tab": 0,
  "session": {}
}
```

로드 결과는 최소한 `NOT_FOUND`, `LOADED`, `RECOVERED_BACKUP`, `CORRUPT`, `NEWER_SCHEMA`를 구분합니다.

저장은 임시 파일 작성과 검증, 이전 주 저장의 백업 회전, 새 주 저장 교체 순서로 처리합니다. 상태 변경 명령 성공 직후, 주기 저장, 앱 일시정지 시점에 저장하되 종료 콜백만 믿지 않습니다.

### 오프라인 진행

- 도메인과 `GameSession`은 시스템 시계를 읽지 않습니다.
- `AppRoot`가 현재 시각과 `saved_at_unix`의 차이를 계산합니다.
- 음수 경과는 `0초`, 큰 경과는 앱 정책 상한인 `8시간`으로 제한합니다.
- 현재 시뮬레이터의 이벤트 제한을 넘지 않도록 작은 시간 묶음으로 기존 결정론적 `tick()`을 호출합니다.
- 적용 전·후 스냅숏 차이로 읽기 전용 인수인계 데이터를 만듭니다.
- 결과 적용 시각과 세션을 먼저 저장한 뒤 보고서를 표시합니다.

## 구현 순서

1. 범위·아키텍처 문서를 새 마일스톤으로 갱신합니다.
2. 공통 UI 토큰과 `AppRoot` 화면 골격을 만듭니다.
3. 기존 현장에 단일 세션·오디오를 주입하고 `tick()` 소유권을 옮깁니다.
4. `GameSession`의 원자적 저장 내보내기·복원을 구현하고 검증합니다.
5. 주 저장·백업·복구 상태가 있는 `SaveRepository`를 구현합니다.
6. 첫 근무, 운영실, 설정, 복구 화면을 회색 상자로 연결합니다.
7. 백그라운드·복귀 집계와 야간 인수인계를 구현합니다.
8. 버전 업데이트 확인·완료 보고서와 플레이형 온보딩을 연결합니다.
9. 와이어프레임 승인 뒤 운영실 전용 픽셀 에셋과 화면별 오디오를 제작합니다.

## 완료 조건

- 근무 기록이 없으면 첫 근무 화면, 정상 기록이면 운영실, 손상 기록이면 복구 화면으로 정확히 분기합니다.
- 첫 실행은 시스템 스플래시 뒤 한 번의 주 버튼으로 플레이형 온보딩에 들어갑니다.
- 정상 완전 재실행은 한 번의 `현장 복귀`로 기존 게임에 들어갑니다.
- 짧은 앱 전환은 같은 화면과 활성 현장 탭으로 즉시 돌아옵니다.
- 운영실·설정·현장을 왕복해도 같은 `GameSession`을 유지합니다.
- 오프라인 결과를 같은 저장에서 두 번 적용할 수 없습니다.
- 오프라인 진행이 패치 선택이나 버전 업데이트를 자동 실행하지 않습니다.
- 주 저장이 손상되면 백업 복구가 가능하고, 둘 다 손상되면 명시적 복구 화면을 표시합니다.
- 버전 업데이트가 초기화·보존 항목을 실행 전에 보여주고, 성공한 저장 뒤에만 완료 보고서를 엽니다.
- 설정 초기화와 근무 기록 초기화가 서로의 데이터를 삭제하지 않습니다.
- 모든 상호작용은 실제 안전 영역 안에 있고 터치 영역이 `48×48px` 이상입니다.
- 뒤로가기, 일시정지·복귀, 저장 실패가 정의된 상태표와 일치합니다.
- 기존 도메인 회귀 테스트, 새 저장·라우팅 테스트, 헤드리스 메인 장면 실행이 모두 통과합니다.
