# 앱 셸·Product V2 수명주기 명세

## 문서 상태

- 상태: Product V2 앱 셸·schema 3 구현 권위
- 대상 마일스톤: 앱 셸, 로컬 저장·복구·복귀와 Product V2 단계 전환
- 기준 해상도: 세로 `360×640`
- 현재 본편: 주간·야간·결과, schema 3
- Legacy V1: 20스테이지, schema 2 이관·회귀 기준

> Product V2 전투는 [혼합 디펜스 전투 명세](COMBAT_HYBRID_SPEC.md)를 따릅니다.
> schema 1·2 기록은 schema 3 후보로 명시적이고 원자적으로 전환합니다.

> 콜드 부트 타이틀과 첫 근무 프롤로그의 상세 계약은 [오프닝 경험 명세](OPENING_EXPERIENCE_SPEC.md)를 따릅니다. 저장 복구, 오프라인 진행, 현장 온보딩과 수명주기 계약은 이 문서가 계속 정의합니다.

이 문서는 앱 실행부터 현장 진입, 복귀, 설정, 버전 업데이트, 저장 오류까지의 화면과 상태를
한곳에서 정의한다. 아래 `Product V2 전환 계약`이 뒤의 Legacy V1 와이어프레임과
오프라인 전투 예시보다 우선한다. 뒤의 V1 내용은 이관·회귀 이력으로 남겨 둔다.

## Product V2 전환 계약

### 재사용과 교체

| 그대로 재사용 | Product V2에서 교체 |
|---|---|
| 타이틀, 프롤로그와 최초 저장 | `OPERATIONS_ROOM`의 자동 운영 요약을 기능형 `DAY_PREP`로 교체 |
| `AppRoot`의 화면·tick·수명주기·오디오 소유권 | 하나의 `GAMEPLAY`를 `DAY_PREP/NIGHT_ACTIVE/SHIFT_RESULT`로 분리 |
| 정확히 하나의 활성 `ProductLoopSession` | 20스테이지와 유지보수·자동 재도전 |
| `SaveRepository`의 원자적 주 저장·백업·복구 | 저장 봉투 버전을 schema 2에서 schema 3으로 올림 |
| 설정과 접근성의 별도 저장 | 운영실·설정 중 전투 계속 |
| 타이틀 복귀, 짧은 앱 전환과 포커스 단일 경로 | 오프라인에서 전투 시뮬레이터 `tick()` 호출 |
| 저장 뒤 읽기 전용 보고서 표시 | 8시간 전투 집계를 12시간 주간 비트 집계로 교체 |

### Product V2 최상위 단계

```text
BOOT
TITLE
PROLOGUE
DAY_PREP
NIGHT_ACTIVE
SHIFT_RESULT
SAVE_RECOVERY
```

- `DAY_PREP`에는 뒤에서 진행할 전투가 없다. 방치 수입, 강화, 패치, 보고서와 다음 근무를
  한 화면 흐름에서 다룬다.
- `NIGHT_ACTIVE`에서 설정·접근성 모달을 열면 전투를 완전히 일시정지한다.
- `SHIFT_RESULT`는 종료된 전투의 읽기 전용 결과이며 보상을 다시 계산하지 않는다.
- `AppRoot`만 단계 전환, 활성 세션 tick, 저장 시점과 오디오 생명주기를 소유한다.
- 화면은 다른 화면을 직접 만들지 않고 의미 신호를 보내며 세션 스냅숏을 읽는다.

### Product V2 실행 경로

```text
첫 설치
BOOT → TITLE → PROLOGUE → 최초 schema 3 저장 → DAY_PREP

정상 완전 재실행
BOOT → TITLE → 저장된 DAY_PREP / NIGHT_ACTIVE / SHIFT_RESULT

야간 시작
DAY_PREP → NIGHT_ACTIVE → SHIFT_RESULT → DAY_PREP

버전 업데이트
DAY_PREP + VERSION_UPDATE_CONFIRM → 원자적 저장 → RUN_SUMMARY → DAY_PREP
```

### Product V2 오프라인 계약

| 저장 단계 | 부재 중 처리 | 복귀 |
|---|---|---|
| `DAY_PREP` | 20분마다 1비트, 최대 12시간·36비트 | 수입 적용·저장 뒤 읽기 전용 인수인계 |
| `NIGHT_ACTIVE` | 전투, 하위 상태와 타이머를 진행하지 않음 | 저장한 정확한 상태에서 재개 |
| `SHIFT_RESULT` | 결과·급여·별·해금을 재계산하지 않음 | 같은 읽기 전용 결과 복원 |

- `AppRoot`가 경과시간을 계산하고 도메인과 `ProductLoopSession`은 시스템 시계를 읽지 않는다.
- 음수 경과는 0으로 처리하고 12시간 이후 수입은 만들지 않는다.
- 같은 포커스 이탈이 여러 플랫폼 알림으로 들어와도 한 번만 적용한다.
- 수입을 세션에 적용한 뒤 먼저 저장하고, 저장 성공 뒤에만 보고서를 보여준다.
- 오프라인으로 전투, 패치 선택, 별·해금과 버전 업데이트를 수행하지 않는다.

### Product V2 버전 업데이트

- 둘째 야간 ★★★ 뒤 `DAY_PREP`에서만 확인창을 열 수 있다.
- 초기화: 비트는 30으로 교체, 요원 레벨, 장착 패치, 현재 버전의 두 야간 진행·별·최초
  보상, 재도전 2배속, 전투 상태, 마지막 결과와 현장 보고서 key·행·읽음 상태.
- 보존: 패치노트, 회차 수, 발견한 요원·패치, 열린 슬롯, 레거시 빌드 캐시, 설정,
  접근성, 스토리·도움말 확인 기록.
- 실행 전 초기화·보존 목록을 텍스트로 보여주며 성공한 세션 변경과 저장 뒤에만 완료
  보고서를 연다.

### Product V2 저장 전환

- Product V2 본편은 schema 3를 사용한다.
- `SaveRepository`는 schema 봉투, 파일, 백업과 원자적 교체만 담당하고 세션 필드를
  해석하거나 변환하지 않는다.
- `ProductV2SaveMigrator`가 비활성 Legacy `GameSession`으로 schema 1·2 원본을 먼저
  검증하고, 변환한 schema 3 전체를 새 `ProductLoopSession` 후보로 검증한다.
- `AppRoot`가 로드, 후보 변환·검증, schema 3 저장과 활성 세션 교체 순서를 조정한다.
- schema 1·2의 회차, 메타 재화, 발견 요원·패치, 열린 슬롯과 영구 성장을 보존해
  `DAY_PREP` 후보를 만든다.
- 기존 진행 중 전투를 Product V2 야간 중간 상태로 추측 변환하지 않는다.
- schema 3은 마지막 읽기 전용 `last_result`, 최신 현장 보고서 key·행과 읽음
  상태를 저장한다. 결과를 다시 열거나 앱을 재실행해도 보상은 재지급되지 않고, 읽은
  보고서는 새 실패 key가 생기기 전까지 다시 알림 상태가 되지 않는다.
- 후보 DTO 전체를 검증하고 schema 3 저장이 성공한 뒤에만 활성 세션을 교체한다.
- 전환 실패는 기존 세션과 파일을 유지하고 명시적 저장 복구 화면으로 보낸다.

## Legacy V1에서 구현 완료된 제품 결정

1. 정상 콜드 부트는 타이틀에서 시작합니다. 첫 실행은 `게임 시작` 뒤 5단계 프롤로그를 완료하거나 건너뛰고, 최초 저장 성공 뒤 현장의 플레이형 온보딩을 시작합니다.
2. 정상 기록이 있는 완전 재실행은 타이틀의 `이어하기` 뒤 `야간 운영실`로 들어갑니다. 의미 있는 부재 결과가 있으면 그 위에 `야간 인수인계`를 한 번 표시합니다.
3. 짧은 앱 전환은 스플래시, 운영실, 복귀 팝업 없이 마지막 화면과 탭을 그대로 복원합니다.
4. 운영실이나 설정을 보고 있는 동안 활성 회차의 자동 전투는 계속됩니다.
5. 앱이 백그라운드에 들어가면 실시간 전투를 중단하고, 복귀할 때 저장된 시각을 기준으로 결정론적으로 집계합니다.
6. 오프라인 진행은 현재 요원과 패치 구성만 사용합니다. 패치 선택이나 버전 업데이트를 대신 수행하지 않습니다.
7. 복귀 결과는 먼저 세션에 적용하고 저장한 뒤 읽기 전용 보고서로 보여줍니다. 보고서를 다시 열어도 보상이 중복 지급되지 않습니다.
8. 현장 실패 보고서는 보상 창이 아니라 최신 실패의 사실을 다시 읽는 화면입니다. 열람 여부가 전투·재화·저장 결과를 바꾸지 않습니다.
9. 모바일 pause/resume과 Web·desktop focus-out/focus-in은 같은 저장·오프라인 경로를 사용하며 한 번의 이탈을 중복 적용하지 않습니다.
10. 진행 저장과 사용자 설정은 분리합니다. 근무 기록을 초기화해도 소리와 접근성 설정은 유지합니다.
11. 광고, 상점, 출석, 우편함, 계정, 클라우드 저장, 라이브 이벤트는 이 마일스톤에 넣지 않습니다.

## Legacy V1 화면 구조

### 최상위 화면

동시에 하나만 존재합니다.

```text
BOOT
TITLE
PROLOGUE
OPERATIONS_ROOM
GAMEPLAY
SAVE_RECOVERY
```

### 오버레이

최상위 화면 위에 동시에 하나만 엽니다.

```text
NONE
OFFLINE_REPORT
SETTINGS
VERSION_UPDATE_CONFIRM
RUN_SUMMARY
ONBOARDING
```

`OverlayHost`가 소유한 앱 셸 오버레이 위에는 또 다른 앱 셸 오버레이를 쌓지 않습니다. 파괴적 확인이 필요하면 현재 오버레이의 내용을 확인 상태로 바꿉니다.

현장 실패 보고서와 자원 설명 말풍선은 `MainView` 내부의 게임플레이 표면입니다. 실패 보고서는 열려 있는 동안 배경을 어둡게 하고 하위 입력을 막는 모달이며, 자원 설명은 레이아웃과 입력을 바꾸지 않는 일시적 말풍선입니다. 둘은 위 앱 셸 오버레이 슬롯에 포함하지 않습니다.

## Legacy V1 실행 경로

```text
첫 설치
시스템 스플래시 → BOOT → TITLE → PROLOGUE → 최초 저장 → GAMEPLAY + ONBOARDING

정상 완전 재실행, 변화 없음
시스템 스플래시 → BOOT → TITLE → OPERATIONS_ROOM → GAMEPLAY

정상 완전 재실행, 변화 있음
시스템 스플래시 → BOOT → TITLE → OPERATIONS_ROOM + OFFLINE_REPORT → GAMEPLAY

짧은 앱 전환
마지막 최상위 화면과 오버레이 없는 상태로 즉시 복원

저장 이상
시스템 스플래시 → BOOT → SAVE_RECOVERY

버전 업데이트
GAMEPLAY + VERSION_UPDATE_CONFIRM → 저장 성공 → RUN_SUMMARY → GAMEPLAY
```

Android 시스템 스플래시 뒤 로컬 복원이 `300ms` 안에 끝나면 별도 부트 문구를 그리지 않습니다. 더 길어질 때만 `근무 기록 확인 중…`을 표시하며 가짜 진행률은 사용하지 않습니다. Web에서는 브라우저 탭이나 창의 포커스를 잃으면 짧은 앱 전환과 같은 백그라운드 경로를 사용합니다.

## Legacy V1 기능 와이어프레임

아래 배치는 실제 `360×640` 화면 안의 정보 우선순위를 정의합니다. 장식용 픽셀 아트는 와이어프레임 승인 뒤 추가합니다.

### 1. 첫 근무 시작

```text
┌──────────────────────────────────┐
│ PIXEL NIGHT SHIFT          [설정] │ 52
│                                  │
│          [요원·서버실 삽화]       │
│                                  │
│          픽셀 야간근무            │
│          서버가 살아있다           │
│                                  │
│ 전투는 요원들이 맡습니다.          │
│ 병목을 진단하고 패치를 선택하세요. │
│                                  │
│        [ 첫 근무 시작 ]           │ 52
└──────────────────────────────────┘
```

- 최초 한 번만 표시합니다.
- 설정 버튼의 터치 영역은 `48×48` 이상입니다.
- `첫 근무 시작` 직후 새 세션을 만들고 최초 저장에 성공한 다음 현장으로 전환합니다.
- 최초 저장 실패 시 현장 진입 전에 오류를 명확히 알립니다.

### 2. 야간 운영실

```text
┌──────────────────────────────────┐
│ 야간 운영실              [설정]  │ 52
│ 야간근무 2회차 · 자동 운영 중     │
│                                  │
│       [운영실 상태 삽화]           │ 192~224
│                                  │
│ 현재 현장        STAGE 14         │
│ 주요 병목        처리량 부족       │
│ 장착 패치        2 / 3            │
│ 다음 목표        감시견 · ST 20    │
│                                  │
│ 방금 저장됨                       │
│        [ 현장 복귀 ]              │ 52
│ [운영 매뉴얼]          [설정]      │ 48
└──────────────────────────────────┘
```

- 운영실은 상태 요약과 진입만 담당합니다.
- 요원 강화와 패치 교체를 운영실에 복제하지 않습니다.
- `현장 복귀`는 유일한 주 행동입니다.
- 저장 실패 중에는 `저장되지 않음`을 위험 상태로 계속 표시합니다.

### 3. 야간 인수인계

운영실 위 최대 `328px` 폭의 모달입니다.

```text
┌──────────────────────────────┐
│ 야간 인수인계                 │
│ 2시간 14분 동안의 자동 운영   │
│ 결과입니다.                   │
│                              │
│ 회수한 비트       +12.4K      │
│ 진행             ST 14 → 17  │
│ 정체 지점         STAGE 17    │
│ 정체 원인         예상 처치가 │
│                  4.8초 느림   │
│                              │
│ 결과는 근무 기록에 이미       │
│ 반영되었습니다.                │
│ [ 정체 지점 확인 ]             │
│ [ 운영실 보기 ]                │
└──────────────────────────────┘
```

- 병목이 없으면 주 버튼은 `현장 복귀`입니다.
- 집계 상한에 닿으면 `8시간 이후의 결과는 집계되지 않았습니다.`를 덧붙입니다.
- 실제 변화가 없으면 표시하지 않습니다.
- 보고서를 닫는 행동은 보상 지급 행동이 아닙니다.

초기 보고서 표시 정책은 다음과 같습니다.

```text
표시 = 가시적인 진행 변화가 있고 다음 중 하나를 만족
  - 부재 시간 120초 이상
  - 스테이지가 바뀜
  - 보스·유지보수·완료 상태가 바뀜
  - 8시간 집계 상한에 닿음
```

`120초`와 `8시간`은 플레이테스트 가능한 앱 정책 값이며 도메인 규칙에 하드코딩하지 않습니다.

### 4. 현장

현재 구현된 게임 화면을 유지합니다. 변경점은 다음에 한정합니다.

- `MainView`가 세션과 오디오를 직접 생성하지 않고 앱 셸로부터 전달받습니다.
- `MainView`가 전투 시간을 직접 진행하지 않습니다.
- 헤더의 음악·효과음 토글은 하나의 `설정` 진입점으로 정리합니다.
- `버전 업데이트` 버튼은 즉시 초기화하지 않고 확인 오버레이를 요청합니다.
- 현장에서 운영실로 나가도 같은 세션과 활성 탭을 유지합니다.
- 비트·패치노트·스테이지 칩은 최소 `48px` 터치 영역을 사용합니다. 마우스를 올리거나 터치하면 의미를 설명하는 말풍선을 해당 아이콘 가까이에 표시합니다.
- 자원 말풍선은 화면 좌우를 벗어나지 않도록 보정하고 아래 공간이 부족하면 아이콘 위에 표시합니다. 마우스가 벗어나면 닫히며 터치한 설명은 약 `2.8초` 뒤 닫힙니다.

#### Legacy V1·Legacy Combat V2·Product V2 현장 실패 보고서

- 보고서 아이콘은 항상 노출합니다. 아직 보고서가 없으면 아이콘 옆 말풍선으로 그 사실만 알립니다.
- Legacy V1에서는 유지보수 진입을 만든 보스 실패가 새 보고서를 만듭니다.
- Legacy Combat V2 격리 모드에서는 `normal_failure` 또는 `boss_failure`가 새 보고서를
  만듭니다.
- Product V2에서는 서버 안정도 0, 보스 30초 시간초과 또는 보스전 전원 쓰러짐이 새
  보고서를 만듭니다.
- 새 보고서는 깜빡임으로 알리며 동작·점멸 감소 설정에서는 정적인 주의 색으로 대체합니다.
- 아이콘을 누르면 읽음으로 바뀌어 강조가 멈춥니다. 보고서 자체는 남아 있어 같은 아이콘으로 다시 열 수 있습니다.
- 같은 실패 키는 재알림하지 않습니다. 다음 실패가 발생하면 최신 사실 기반 행 최대 2개로 교체하고 다시 읽지 않음 상태가 됩니다.
- 카드는 읽기 전용입니다. 카드를 누르는 요원 강화 이동, 전투 명령, 숨은 보너스나 불이익은 없습니다.
- 보고서는 현재 탭을 바꾸거나 요원 강화 목록의 레이아웃에 참여하지 않는 독립 모달입니다.
- 모달은 좌우 `16px`, 상하 `48px` 안전 여백, `48px` 닫기 버튼과 내부 세로 스크롤을 사용합니다. 닫기 버튼 또는 어두운 바깥 영역의 클릭·터치로 닫습니다.
- Legacy V1의 보고서 키·행·읽음 상태는 `AppRoot`가 앱 실행 중 캐시하고 모달 표현은
  `MainView`가 소유합니다. 현재 Product V2는 위 schema 3 계약에 따라 최신 보고서와
  읽음 상태를 저장하되 화면은 여전히 읽기 전용으로만 표현합니다.

### 9. 플레이형 온보딩

세계와 플레이어 역할은 [오프닝 경험 명세](OPENING_EXPERIENCE_SPEC.md)의 짧은 프롤로그가 담당합니다. 조작 설명은 별도 슬라이드로 복제하지 않고 기존 현장 위에서 세 단계로 진행합니다.

1. **전투는 요원들이 맡습니다.** `먼저 지켜보세요. 반복해서 누를 필요는 없습니다.` 버튼: `확인`
2. **병목이 감지되었습니다.** `진단 카드에서 느려진 원인을 확인하세요.` 버튼: `진단 보기`
3. **대응 방법은 하나가 아닙니다.** `요원을 강화하거나, 장점과 부작용이 있는 패치를 선택하세요.` 버튼: `직접 판단하기`

설명 카드는 강조 대상을 가리지 않도록 화면 위·아래를 바꾸며 배치합니다. 언제든 건너뛸 수 있고 설정에서 다시 볼 수 있습니다.

### 치수

- 실제 안전 영역 안에 다시 좌우 `8px` 콘텐츠 여백을 둡니다.
- 주요 버튼 높이는 `52px`, 모든 터치 영역은 최소 `48×48px`입니다.
- 설명 화면 본문은 `11~12px`, 보조문은 최소 `10px`, 제목은 `15~20px`입니다.
- 패널 간격은 현장 `4px`, 운영실·설명 화면 `8~12px`입니다.
- 기본 테두리 `1px`, 선택·위험 강조 `2px`, 모서리 `4px`를 사용합니다.
- 화면이 짧으면 글자를 줄이는 대신 세로 스크롤을 허용합니다.
- 중요한 상태는 색, 아이콘, 텍스트 표지를 함께 사용합니다.
- 전투 HP와 피해량은 소수점을 버린 정수로 표시합니다. 보스 HP 상세 줄은 글꼴의 위·아래 픽셀이 잘리지 않는 최소 높이를 확보합니다.

### 에셋 재사용

- 운영실 현황: `bit`, `patch_note`, `stage`, `diagnosis`
- 현장 복귀: `combat`
- 야간 인수인계: `maintenance`, 보스 정체 시 `boss`
- 업데이트 완료: `complete`
- 첫 화면: 네 요원과 기존 서버실 띠를 임시 조합

`battle_server_room.png`는 `344×64` 전투 띠이므로 운영실 전체 배경으로 확대하지 않습니다. 운영실 전용 배경과 설정·저장·인수인계 아이콘은 와이어프레임 확인 뒤 생성기, 매니페스트, 검증기를 함께 확장합니다.

## 구현 계약

```text
AppRoot
```

- 각 화면은 다른 화면을 직접 열지 않고 `night_requested`, `settings_requested`, `version_update_requested` 같은 의미 신호만 보냅니다.
- Product V2 화면은 활성 세션과 오디오 참조를 트리 진입 전에 주입받습니다.
- 화면 내부의 세션·오디오 생성과 전투 `tick()`은 금지합니다.
- 현재 V1의 운영실·설정 중에는 `AppRoot`가 전투를 계속 진행합니다. Product V2에서는
  위 전환 계약에 따라 주간·결과에 배경 전투가 없고 야간 설정은 전투를 멈춥니다.
- 백그라운드에서는 실시간 `tick()`을 멈춥니다.
- 전역 이벤트 버스와 여러 Autoload를 추가하지 않습니다.

### 저장 경계

```text
game/persistence/save_repository.gd
game/persistence/save_load_result.gd
```

`SaveRepository`는 파일과 저장 봉투만 책임지고, 세션 데이터는 불투명한 `Dictionary`로 취급합니다.

```gdscript
SaveRepository.load() -> SaveLoadResult
SaveRepository.save(
    session_data: Dictionary,
    saved_at_unix: int,
    last_gameplay_tab: int
) -> Error

ProductLoopSession.export_state() -> Dictionary
ProductLoopSession.restore_state(data: Dictionary) -> PackedStringArray
```

- `snapshot()`은 화면 DTO이며 저장 데이터로 사용하지 않습니다.
- `export_state()`는 저장 전용 DTO입니다.
- 복원은 새 상태 후보를 전부 검증한 뒤 한 번에 교체합니다.
- 복원 실패는 현재 세션을 변경하지 않습니다.
- 누락 키, 비정상 숫자, 알 수 없는 콘텐츠 ID를 조용한 기본값으로 바꾸지 않습니다.

저장 봉투의 최초 형태:

```json
{
  "schema_version": 1,
  "saved_at_unix": 0,
  "last_gameplay_tab": 0,
  "session": {}
}
```

로드 결과는 최소한 `NOT_FOUND`, `LOADED`, `RECOVERED_BACKUP`, `CORRUPT`, `NEWER_SCHEMA`를 구분합니다.

저장은 임시 파일 작성과 검증, 이전 주 저장의 백업 회전, 새 주 저장 교체 순서로 처리합니다. 상태 변경 명령 성공 직후, 주기 저장, 앱 일시정지 시점에 저장하되 종료 콜백만 믿지 않습니다.

### Legacy V1 오프라인 진행

- 도메인과 `GameSession`은 시스템 시계를 읽지 않습니다.
- `AppRoot`가 현재 시각과 `saved_at_unix`의 차이를 계산합니다.
- 모바일 pause/resume과 Web·desktop focus-out/focus-in은 `AppRoot`의 같은 진입점을 호출합니다.
- 한 번 백그라운드로 전환된 뒤 중복 알림이 와도 추가 저장·추가 집계를 만들지 않습니다.
- 음수 경과는 `0초`, 큰 경과는 앱 정책 상한인 `8시간`으로 제한합니다.
- 현재 시뮬레이터의 이벤트 제한을 넘지 않도록 작은 시간 묶음으로 기존 결정론적 `tick()`을 호출합니다.
- 적용 전·후 스냅숏 차이로 읽기 전용 인수인계 데이터를 만듭니다.
- 결과 적용 시각과 세션을 먼저 저장한 뒤 보고서를 표시합니다.

## Legacy V1 구현 이력

아래 앱 셸 작업은 모두 완료됐습니다.

1. 범위·아키텍처 문서를 새 마일스톤으로 갱신합니다.
2. 공통 UI 토큰과 `AppRoot` 화면 골격을 만듭니다.
3. 기존 현장에 단일 세션·오디오를 주입하고 `tick()` 소유권을 옮깁니다.
4. `GameSession`의 원자적 저장 내보내기·복원을 구현하고 검증합니다.
5. 주 저장·백업·복구 상태가 있는 `SaveRepository`를 구현합니다.
6. 첫 근무, 운영실, 설정, 복구 화면을 회색 상자로 연결합니다.
7. 백그라운드·복귀 집계와 야간 인수인계를 구현합니다.
8. 버전 업데이트 확인·완료 보고서와 플레이형 온보딩을 연결합니다.
9. 와이어프레임 승인 뒤 운영실 전용 픽셀 에셋과 화면별 오디오를 제작합니다.

## Legacy V1 완료 조건

- 근무 기록이 없거나 정상 기록이면 타이틀, 손상 기록이면 복구 화면으로 정확히 분기합니다.
- 첫 실행은 타이틀과 프롤로그 뒤 최초 저장에 성공해야 플레이형 온보딩에 들어갑니다.
- 정상 완전 재실행은 `이어하기`로 운영실에 들어간 뒤 `현장 복귀`로 기존 게임에 들어갑니다.
- 짧은 앱 전환은 같은 화면과 활성 현장 탭으로 즉시 돌아옵니다.
- 운영실·설정·현장을 왕복해도 같은 `GameSession`을 유지합니다.
- 오프라인 결과를 같은 저장에서 두 번 적용할 수 없습니다.
- 오프라인 진행이 패치 선택이나 버전 업데이트를 자동 실행하지 않습니다.
- 주 저장이 손상되면 백업 복구가 가능하고, 둘 다 손상되면 명시적 복구 화면을 표시합니다.
- 버전 업데이트가 초기화·보존 항목을 실행 전에 보여주고, 성공한 저장 뒤에만 완료 보고서를 엽니다.
- 새 실패 보고서는 읽지 않음 알림 뒤 독립 모달로 열리고, 읽음 상태에서도 재열람할 수 있으며 다음 실패 때 최신 내용으로 교체됩니다.
- 자원 설명 말풍선과 실패 보고서가 360×640 화면 경계와 주요 전투 레이아웃을 깨뜨리지 않습니다.
- 설정 초기화와 근무 기록 초기화가 서로의 데이터를 삭제하지 않습니다.
- 모든 상호작용은 실제 안전 영역 안에 있고 터치 영역이 `48×48px` 이상입니다.
- 뒤로가기, 일시정지·복귀, 저장 실패가 정의된 상태표와 일치합니다.
- 기존 도메인 회귀 테스트, 새 저장·라우팅 테스트, 헤드리스 메인 장면 실행이 모두 통과합니다.
