# 본편 혼합 전투 플레이테스트

> 현재 전투 완성도 마일스톤의 시간·전투 규칙은 [본편 혼합 전투 완성도 명세](COMBAT_HYBRID_SPEC.md)를 따릅니다.

## 목적

콘텐츠 양이 아니라 `병목 관찰 -> 강화·패치 판단 -> 보스 위험 변화 -> 버전 업데이트`가
재미와 이해 가능한 선택을 만드는지 확인한다. 플레이 시간이 단순 대기가 아니라 판단에서 생기는지도 함께 확인한다.

## 테스트 경로

### 관찰자가 같은 PC에서 진행하는 경우

참가자마다 고유한 세션 ID를 사용해 실제 근무 기록과 분리합니다.

```powershell
.\tools\run_godot_manual_e2e.ps1 -SessionId playtest-participant-01
```

### 친구가 원격으로 진행하는 경우

아래 GitHub Pages 링크를 전달합니다.

`https://dudcjfsp-cyber.github.io/pixel-night-shift/`

- 진행은 기기·브라우저별 로컬 저장입니다. 계정이나 클라우드 동기화는 없습니다.
- 같은 기기에서 참가자를 바꿀 때는 이 사이트의 저장 데이터를 지우거나 새 비공개 창을 사용합니다.
- 새로고침 후 이어하기를 확인해야 하므로 테스트가 끝날 때까지 같은 브라우저 저장소를 유지합니다.
- 배포 링크가 열려도 자동 테스트 통과를 뜻하지 않습니다. 관찰자는 배포 전에 저장소의 검증 명령을 별도로 통과시킵니다.

## 진행

1. 설명 없이 새 게임을 시작한다.
2. 관찰자는 조작 방법을 가르치지 않고 막히는 지점과 발화를 기록한다.
3. 참가자는 스테이지 20을 통과하거나 40분이 지나면 첫 회차를 종료한다.
4. 버전 업데이트가 열렸을 때 스스로 선택하는지 확인한다.
5. 업데이트를 선택했다면 두 번째 회차의 첫 보스까지 진행한다.

원격 테스트에서는 시작 전에 다음 환경만 기록합니다.

- 배포 기준 커밋 SHA와 GitHub Pages Actions 실행 URL
- 기기와 OS
- 브라우저와 대략적인 화면비
- 가로·세로 중 실제 플레이 방향
- 이어폰·스피커·무음 여부

## 화면·수명주기 체크

- 첫 로딩 뒤 타이틀의 한글이 깨지지 않고 `픽셀 야간근무`와 `서버가 살아있다`가 구분된다.
- 첫 클릭·터치 뒤 타이틀 음악이 시작되고 프롤로그에서 끊기지 않는다.
- 타이틀 → 프롤로그 → 현장 온보딩 → 자동 전투가 막힘 없이 이어진다.
- 비트·패치노트·스테이지 아이콘을 마우스로 올리거나 터치했을 때 해당 아이콘 근처에 설명 말풍선이 뜬다.
- 말풍선이 화면 밖으로 잘리거나 하단 전투 피드백을 바꾸지 않는다.
- 보스 실패 뒤 현장 보고서 아이콘이 새 보고서를 알리고, 열면 독립 모달에서 글과 작은 요원 초상화가 함께 보인다.
- 보고서를 닫은 뒤 아이콘은 남고 강조만 멈추며, 같은 보고서를 다시 열 수 있다.
- 다음 보스 실패가 발생하면 보고서 내용이 최신 사실로 바뀌고 읽지 않음 강조가 다시 시작된다.
- 보고서가 요원 강화 목록을 밀어내지 않고 열린 동안 뒤쪽 버튼 입력을 막는다.
- 보스 HP·제한 시간·다음 행동과 네 요원의 정수 HP·PROCESS DOWN 문구가 잘리지 않는다.
- 브라우저 탭 전환 또는 화면 잠금 뒤 돌아왔을 때 진행이 한 번만 반영되고 같은 화면과 탭으로 복귀한다.
- 새로고침 뒤 `이어하기`가 보이고 기존 근무 기록으로 운영실과 현장에 돌아갈 수 있다.
- 길이가 다른 Galaxy 계열 화면에서도 좌우 잘림, 하단 버튼 가림과 과도한 빈 공간이 없다.

## 통과 기준

- 5명 중 4명이 병목 발생 후 10초 안에 원인을 설명한다.
- 5명 중 4명이 보스의 DOWN 위험과 QA 구조 상태를 별도 설명 없이 이해한다.
- 5명 중 4명이 별도 설명 없이 진단 카드와 패치 화면을 찾는다.
- 5명 중 4명이 첫 실패 뒤 현장 보고서를 열고 그 근거를 설명한다.
- 5명 중 3명이 30초 안에 타당한 강화 또는 패치 변경을 수행한다.
- 5명 중 4명이 적용한 패치의 이점과 부작용을 설명한다.
- 패치 적용 후 3초 안에 전투 변화가 인지된다.
- 첫 보스는 평균 1~3회 실패 후 통과하고 누구도 같은 원인으로 5회 이상 막히지 않는다.
- 스테이지 20 보스는 평균 1~4회 실패 후 통과한다.
- 5명 중 4명이 첫 회차를 35분 안에 완료한다.
- 5명 중 3명이 강요 없이 버전 업데이트를 선택한다.
- 두 번째 회차의 첫 보스 도달 시간이 첫 회차보다 25% 이상 짧다.

## 실패 시 우선 수정

- 병목을 이해하지 못함: 콘텐츠를 추가하지 않고 진단 근거와 표현을 수정한다.
- 패치 차이를 느끼지 못함: 수치 차이와 화면 피드백을 강화한다.
- 항상 같은 패치가 정답임: 장점과 부작용 또는 보스 규칙을 다시 조정한다.
- 보스에서 장시간 정체됨: 유지보수 파밍과 교체 비용을 먼저 조정한다.
- DOWN 또는 QA 구조를 이해하지 못함: 전투 규칙을 늘리지 않고 보스 경고와 상태 표현을 먼저 수정한다.
- 실패 보고서를 찾지 못함: 영구 패널을 추가하지 않고 아이콘의 읽지 않음 강조와 실패 직후 동선을 먼저 수정한다.
- 글자·HP·말풍선이 잘림: 글자 크기를 줄이기 전에 컨테이너 여백, 내부 스크롤과 화면 경계 보정을 수정한다.
- 탭 복귀·새로고침에서 진행이 중복됨: 콘텐츠를 조정하지 않고 수명주기 저장·복귀 경계를 차단 문제로 처리한다.
- 버전 업데이트를 피함: 초기화 항목, 유지 항목, 예상 단축 시간을 더 명확히 보여준다.

플레이테스트 로그에는 개인정보를 넣지 않으며, 전투 시도 단위의 집계만 기록한다.
