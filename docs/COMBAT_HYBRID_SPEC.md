# Product V2 혼합 디펜스 전투 명세

## 문서 상태

- 상태: Product V2 구현 권위
- 대상 마일스톤: 주간 방치 정비와 야간 10웨이브 자동 디펜스
- 기준 엔진: Godot 4.7, typed GDScript
- 기준 화면: 세로 `360×640`
- 제품 결정 원본: [Product V2 계획표](PRODUCT_V2_PLAN.md)

현재 배포 본편은 20스테이지, 스테이지 10·20의 25초 보스, 유지보수 파밍과 자동 재도전을
사용한다. Product V2가 6단계에서 본편으로 승격되기 전까지 코드는 그 V1 동작을 유지한다.
이 문서는 목표 전투를 정의하며 현재 코드 동작을 이미 완료된 것처럼 설명하지 않는다.
현재 V1의 상세 회귀 기준은 [V1 전투 동결 기준선](V1_COMBAT_BASELINE.md)에 보존한다.

### 세대 구분

| 이름 | 의미 |
|---|---|
| 현재 본편 V1 | 20스테이지 연속 전투와 25초 보스, 유지보수·자동 재도전을 사용하는 배포 구현 |
| Legacy Combat V2 | 일반 적 공격, 6초 복구와 긴급 재배포가 있는 격리 10스테이지 비교 실험 |
| Product V2 | 이 문서가 정의하는 `DAY_PREP → NIGHT_ACTIVE → SHIFT_RESULT` 제품 |
| Defense Lab | Product V2 전투를 본편 승격 전에 검증하는 격리 실행 경로 |

Legacy Combat V2를 Product V2 엔진으로 승격하거나 현재 V1 시뮬레이터에 조건 분기를 계속
추가하지 않는다.

## 목표

> 주간에 실패 원인을 고쳐 편성을 준비하고, 60~80초의 야간 자동 디펜스에서 서버가
> 얼마나 오래 버티고 보스까지 처리하는지 확인한다.

전투는 자동이지만 결과는 다음 주간 판단과 직접 연결돼야 한다.

- 어떤 적이 침입했고 안정도가 얼마나 줄었는지 읽을 수 있다.
- HP와 제한시간을 서로 혼동하지 않는다.
- 공격 발사, 도착, 피격과 HP 감소가 한 사건처럼 보인다.
- 실패 결과가 누구를 강화하거나 어떤 패치를 비교할지 근거를 제공한다.
- 실패는 긴 구간을 되감거나 자동 파밍을 기다리게 하지 않는다.

## 변경하지 않는 제품 원칙

- 공격, 타기팅, 적 이동, 보스 행동과 QA 구조는 자동이다.
- 수동 공격, 액티브 스킬, 회피, 타워 배치와 실시간 긴급 재배포를 추가하지 않는다.
- 야간 중 요원 강화와 패치 교체를 허용하지 않는다.
- 같은 상태와 동일한 시간 입력은 tick 분할과 프레임률에 관계없이 같은 결과를 만든다.
- 도메인은 장면, 노드, 파일, 시스템 시계와 오디오에 의존하지 않는다.
- 플레이어의 명령은 애플리케이션 경계를 거치고 화면은 스냅숏만 읽는다.
- 기본 콘텐츠는 기존 요원 4명, 패치 5개와 보스 1종을 재사용한다.
- 신규 요원, 패치, 적, 보스, 근무와 재화를 추가하지 않는다.

## 한 야간의 구조

```text
COUNTDOWN 2초
  → NORMAL_ACTIVE 웨이브 1
  → INTER_WAVE 0.4초
  → ...
  → NORMAL_ACTIVE 웨이브 9
  → BOSS_WARNING 1초
  → BOSS_ACTIVE 웨이브 10
  → SUCCESS 또는 FAILURE
```

| 항목 | 값 |
|---|---:|
| 일반 웨이브 | 9 |
| 일반 웨이브 최대 처리시간 | 5초 |
| 조기 전멸 전환 | 실시간 0.4초 |
| 보스 경고 | 실시간 1초 |
| 보스 제한시간 | 30초 |
| 전투 시계 최대 | 75초 |
| 보통 완주 체감 목표 | 60~80초 |

시작 카운트다운, 웨이브 전환과 보스 경고는 전투 시계를 멈춘 표시 상태다. 모두 저장 가능한
명시적 하위 상태이며 오프라인에서 진행하지 않는다. 웨이브 9 뒤에는 0.4초 전환을 생략하고
1초 보스 경고만 사용한다.

## 일반 웨이브

### 서버 안정도와 침입

| 항목 | Defense Lab 초기값 |
|---|---:|
| 최대·야간 시작 안정도 | 100 |
| 소형 적 침입 피해 | 5 |
| 일반 적 침입 피해 | 10 |
| 급증 적 침입 피해 | 20 |
| 한 웨이브 침입 피해 상한 | 40 |
| 위험 경고 | 안정도 40 이하 또는 다음 예상 침입 피해가 현재 안정도 이상 |

- 적을 5초 안에 모두 처리하면 침입 없이 0.4초 전환으로 이동한다.
- 5초와 같은 시각에 예약된 요원 공격·피격·처치를 먼저 처리한다.
- 그 뒤 살아 있는 적의 침입 피해를 합산하고 40에서 제한한다.
- 생존 적은 한 번의 침입 묶음으로 코어에 도달하고 해당 웨이브에서 제거된다.
- 상한이 적용되면 `안정도 -40 · 웨이브 피해 상한`을 표시한다.
- 안정도가 0이 되면 현재 웨이브를 완료로 세지 않고 즉시 실패한다.
- 안정도가 남으면 침입 여부와 관계없이 현재 웨이브를 완료하고 다음 전환으로 이동한다.
- 일반 적은 요원을 공격하지 않고 일반전 `PROCESS DOWN`을 만들지 않는다.

### 첫째 야간 초기 편성

| 웨이브 | 적 수·침입 등급 | HP 배율 | 학습·위험 신호 |
|---:|---|---:|---|
| 1 | 일반 3 | ×1.00 | 이동·피격·침입 규칙 학습 |
| 2 | 일반 3 | ×1.00 | 첫 반복으로 규칙 확인 |
| 3 | 일반 4 | ×1.00 | 첫 별 경계, 최악의 누수에는 0성 실패 가능 |
| 4 | 일반 4 | ×1.25 | HP 증가 |
| 5 | 일반 3 + 급증 1 | ×1.25 | `트래픽 급증` 경고, 선택창 없음 |
| 6 | 일반 5 | ×1.25 | 두 번째 별 경계 |
| 7 | 일반 5 | ×1.55 | 후반 압박 |
| 8 | 일반 6 | ×1.55 | 후반 압박 |
| 9 | 일반 6 | ×1.55 | 보스 접근 경고 |

둘째 야간은 같은 9+1 구조와 시간 규칙을 유지하고 현재 스테이지 11~20의 성장 곡선과
강화된 보스 값을 콘텐츠로 옮긴다. 난이도는 시간을 늘리지 않고 적 HP, 편성, 침입 등급,
보스 행동과 요원 가동률로 조절한다.

첫 시도 시작 요원 2명으로 ★는 안정적으로, ★★는 합리적으로, ★★★도 정확한 초기 강화
배분을 했다면 강제 실패 없이 달성할 수 있어야 한다.

## 보스 웨이브

### 역할과 PROCESS DOWN

| 요원 | 역할 | 관찰 가능한 효과 |
|---|---|---|
| 디버거 | 전열 안정화 | 높은 내구도와 위협도로 팀의 보스 피해를 대신 받음 |
| 빌드 엔지니어 | 보스 화력 | 보스 대상 피해 효율이 높음 |
| 스프라이트 장인 | 팀 템포 | 가동 중 팀 전체 공격 주기를 단축함 |
| QA 임프 | 자동 복구 | 보스 시도당 요원 한 명을 한 번 자동 구조함 |

- 보스 시작 시 해금된 요원은 최대 HP로 시작한다.
- HP가 0이 된 요원은 공격을 중단하고 `PROCESS DOWN`이 된다.
- 일부 요원이 DOWN돼도 남은 요원이 자동 전투를 계속한다.
- 전원 DOWN은 즉시 실패다.
- 역할 수치는 `game/content/operators.json`을 재사용하고 로딩 경계에서 검증한다.
- 요원 DPS·강화 증가량, HP와 피해량은 사용자에게 소수점을 버린 정수로 표시한다.

### 보스 행동

기존 `Watchdog Process`의 행동 종류를 유지한다.

- `POLL`: 가장 높은 위협도의 가동 요원을 주기 공격한다.
- `KILL SIGNAL`: 현재 유효 DPS가 가장 높은 가동 요원을 특수 공격한다.
- `ROLLBACK`: 보스 최대 HP의 일부를 회복한다.
- 둘째 야간 보스: 일정 시점부터 팀 처리량을 낮춘다.

첫 Defense Lab의 행동값은 현재 본편 스테이지 10·20 값을 각각 첫째·둘째 야간 후보로
옮기되 제한시간은 둘 다 30초로 사용한다. 정확한 HP·피해·간격은 Product V2 전용 콘텐츠
파일에서 소유하며 기존 V1 `balance.json`의 25초 값을 변경하지 않는다.

### QA 자동 구조

- QA 임프가 가동 중이고 구조를 아직 쓰지 않았다면 다른 요원의 첫 DOWN에 구조를 예약한다.
- 초기값은 구조 지연 5초, 복귀 HP 40%, 보스 시도당 1회다.
- 구조 완료 전에 QA 임프가 DOWN되면 예약을 취소한다.
- 구조 예약·취소·성공은 화면과 오디오에서 구분한다.
- 구조는 자동이며 플레이어 입력을 기다리지 않는다.

### 같은 시각 판정 순서

같은 시각에 사건이 겹치면 다음 순서를 사용한다.

1. QA 구조 완료
2. 요원 공격과 적·보스 처치
3. 일반 웨이브 제한시각이면 생존 적 침입
4. 안정도 감소와 일반 실패
5. 보스 주기·특수 공격
6. `ROLLBACK`과 둘째 야간 처리량 저하
7. 보스 시간초과
8. 다음 하위 상태 전환

따라서 정확히 5초에 마지막 적을 처치하면 침입하지 않고, 정확히 30초에 보스를 처치하면
성공한다.

## 종료, 별과 실패 근거

### 종료 조건

- 서버 안정도 0
- 보스 제한시간 30초 초과
- 보스전 요원 전원 DOWN
- 보스 처치

종료 뒤 추가 tick은 상태, 급여, 별과 결과를 변경하지 않는다. 자동 유지보수와 자동 재도전을
시작하지 않는다.

### 별

| 완료 웨이브 | 별 |
|---:|---:|
| 0~2 | 0 |
| 3~5 | 1 |
| 6~9 | 2 |
| 10 | 3 |

별은 저장된 가변 전투값이 아니라 완료 웨이브 수와 `[3, 6, 10]` 기준에서 계산한다.
안정도가 0이 된 현재 웨이브는 완료 수에 포함하지 않는다. 남은 안정도는 별이 아니라
근무 급여의 무결성 보너스에만 영향을 준다.

### 실패 근거

도메인은 최소한 다음의 사실을 결과에 남긴다.

- 종료 이유와 완료 웨이브
- 서버 안정도 변화와 가장 큰 침입 묶음
- 일반전 예상 처리량 대비 실제 미처리 적
- 보스 남은 HP와 제한시간 차이
- 요원별 DOWN 시각·원인과 QA 구조 결과
- 보스가 복구한 총 HP와 처리량 저하 시간

보고서는 이 사실을 쉬운 말로 표현하되 스냅숏과 사건으로 증명할 수 없는 원인을 만들지
않는다.

## 배속과 일시정지

- 처음 보는 각 야간은 1배속만 사용한다.
- 해당 `버전 + 야간`을 ★★★로 완료한 뒤 그 야간 재도전에서만 2배속을 연다.
- 2배속은 현실시간 대비 도메인 전투시간의 진행률만 바꾼다.
- 카운트다운, 0.4초 전환과 보스 경고는 배속하지 않는다.
- 설정·접근성 모달을 열면 모든 하위 상태를 완전히 일시정지한다.
- 1배속과 2배속은 같은 입력 상태에서 같은 전투 결과를 만든다.

## 전투 표시 계약

- 직접 피해는 `투사체 도착 → 약 0.1초 피격 점멸·미세 반동 → HP·피해 갱신` 순서다.
- 같은 적에게 빠르게 들어오는 피해 숫자는 약 0.25초 단위로 합친다.
- 적 HP는 대상 가까이의 막대와 정수로, 제한시간은 상단 시계 아이콘과 다른 색으로 표시한다.
- 진행 HUD는 10칸이며 3·6에 별, 10에 보스 표식을 둔다.
- 다음 웨이브의 쉬운 특성명과 아이콘을 한 칸 미리 보여준다.
- 침입은 적 묶음의 코어 도달, 코어 점멸·충격, 안정도 감소 순으로 표시한다.
- 화면 흔들림은 일반 공격에는 사용하지 않는다. 코어 침입은 60~80ms, 보스 특수 충격은
  100~140ms만 사용하고 설정에서 끌 수 있다.
- 중요한 정보는 색상만으로 구분하지 않고 아이콘·형태·텍스트를 함께 사용한다.

## 도메인과 콘텐츠 경계

Product V2 전투는 현재 V1 `GameState`, `BattleSimulator`, `HybridBossSimulator`와 Legacy
`CombatV2State`에 분기를 추가하지 않고 격리된 도메인으로 먼저 구현한다.

```text
game/content/product_v2/
  product_v2.json
  product_v2_catalog.gd
  product_v2_loader.gd

game/domain/product_v2/
  night_shift_state.gd
  night_shift_simulator.gd
```

- Product V2 카탈로그는 기존 요원·패치 정의를 참조하되 웨이브·안정도·시간·별·보스
  후보값을 별도로 소유한다.
- 로더는 정확한 키, 유한한 양수, 1~9 일반·10 보스, 고유 웨이브 번호, 알려진 적 등급과
  손실 상한을 엄격히 검증한다.
- 상태는 하위 상태, 웨이브, 완료 수, 타이머, 안정도, 적·보스·요원 런타임, QA 구조와
  고정된 종료 이유를 소유한다.
- 화면상의 적 위치는 저장하지 않고 웨이브 경과율에서 표시 계층이 계산한다.
- 최근 사건은 표시와 보고서에 필요한 제한된 개수만 유지한다.

Defense Lab 승인 전에는 `GameSession`, `AppRoot`, `project.godot`, V1 콘텐츠와 본편 저장
schema를 변경하지 않는다.

## 저장과 오프라인 경계

2~3단계 Defense Lab은 본편 저장과 분리한다. 단계별 경계는 다음과 같다.

- 2단계는 도메인·콘텐츠를 실행기로 직접 검증하며 애플리케이션 세션이나 화면을 추가하지 않는다.
- 3단계는 별도 `DefenseLabSession`과 격리된 테스트 저장을 사용한다. 실행 경로의 조정자만
  세션 `tick()`을 호출하고 화면은 명령을 전달하며 `snapshot()`만 읽는다.
- 6단계 본편 승격 뒤 기존 `GameSession`이 Product V2 상태와 콘텐츠의 유일한 제품
  애플리케이션 경계가 되고 schema 3를 사용한다.
- 제품 경로에서는 `AppRoot`만 tick, 화면 전환, 수명주기, 저장 시점과 오디오
  생명주기를 소유한다.
- `DAY_PREP`만 20분당 1비트, 최대 12시간·36비트의 오프라인 수입을 적용한다.
- `NIGHT_ACTIVE`는 전투를 진행하지 않고 저장한 정확한 하위 상태에서 재개한다.
- `SHIFT_RESULT`는 결과와 보상을 다시 계산하거나 지급하지 않는다.
- schema 1·2는 기존 메타, 발견과 영구 성장을 보존해 `DAY_PREP` 후보로 원자적 전환한다.
- 잘못되거나 더 최신인 저장은 조용히 초기화하지 않고 명시적으로 거부한다.

## 자동 검증 기준

2단계는 한 개의 실행기에서 다음 핵심 행동만 검증한다.

1. 기본 Product V2 콘텐츠 로드와 대표적인 잘못된 입력 거부
2. 한 번의 큰 tick과 여러 분할 tick의 관찰 상태 동일
3. 정확히 5초의 공격 우선 판정과 조기 전멸 뒤 0.4초 전환
4. 적별 침입 합계·웨이브 상한 40과 완료 3/6/10의 별
5. 정확히 30초 처치 성공, 시간초과와 전원 DOWN 실패

UI, 저장, 급여, 해금과 오프라인 수입은 각각 3~6단계에서 실제 경계가 생길 때 검증한다.
내부 호출 순서나 모든 콘텐츠 조합을 위한 테스트를 만들지 않는다.

## 사람 플레이테스트 완료 기준

- 5명 중 4명이 무엇을 지키는지 설명한다.
- 5명 중 4명이 종료 이유와 다음 주간 행동을 설명한다.
- 5명 중 4명이 적 HP와 남은 제한시간을 구분한다.
- 공격과 HP 감소를 눈으로 연결할 수 있다.
- 보통 완주가 60~80초이며 급하거나 지루하다는 반응이 다수가 아니다.
- 시작 요원 2명으로 강제 실패 없이 ★★★가 원칙적으로 가능하다.
- 5명 중 3명 이상이 `할 일이 없다`고 답할 때만 웨이브 5 관제 지시를 별도 실험한다.
