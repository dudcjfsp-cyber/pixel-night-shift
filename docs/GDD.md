## 문서 상태

- 상태: Product V2 제품 기준
- 기준 엔진: Godot 4.7, typed GDScript
- 기준 화면: 세로 `360×640`
- 상세 제품 결정: [Product V2 계획표](PRODUCT_V2_PLAN.md)
- 다음 재미 검증: [Product V2.1 계획](PRODUCT_V2_1_PLAN.md)
- 권위 전투 규칙: [Product V2 혼합 디펜스 전투 명세](COMBAT_HYBRID_SPEC.md)
- 앱 셸·저장 기반: [앱 셸·Product V2 수명주기 명세](APP_SHELL_SPEC.md)

현재 기본 실행 경로는 schema 3의 Product V2 본편이다. 20스테이지 V1과 Defense Lab은
이관·회귀 비교용으로 보존한다.

## 한 문장 설명

> 낮에는 방치 수입으로 요원과 패치를 정비하고, 밤에는 최대 네 요원이 10웨이브 동안
> 낡은 게임 서버를 지키는 세션형 자동 디펜스 운영 게임.

## 플레이어 역할과 분위기

플레이어는 용사가 아니라 서비스 종료 직전 게임의 야간 운영 책임자다. 요원들은 버그 적을
자동으로 처리하고 플레이어는 서버 안정도, 처리량, 보스 행동과 실패 보고서를 읽어 다음
근무의 강화와 패치를 결정한다.

레트로 게임과 직장 코미디의 정서를 사용하되 특정 참고 작품의 캐릭터, 명칭, 대사, UI
배치, 사건과 시각 구성을 재현하지 않는다. 개발 용어는 알아보면 더 재미있는 풍미로만
사용하고, 핵심 행동과 경고는 일반 플레이어도 이해할 수 있는 쉬운 말로 먼저 표시한다.

## 핵심 원칙

- 야간 공격, 타기팅, 보스 행동과 QA 구조는 완전 자동이다.
- 플레이어는 직접 공격하거나 타워를 배치하지 않는다.
- 의미 있는 행동은 관찰, 진단, 요원 강화, 패치 비교·편성과 버전 업데이트다.
- 주간은 준비가 끝나면 즉시 다음 근무를 시작할 수 있는 정비 단계이며 에너지 대기가 아니다.
- 한 야간은 일반 9웨이브와 보스 1웨이브로 끝나는 짧은 세션이다.
- 실패하면 근무가 끝나고 결과를 확인한 뒤 같은 주간 체크포인트에서 무료 복구한다.
- 자동 유지보수 파밍, 자동 재도전, 광고 배율과 입장 에너지는 사용하지 않는다.
- 같은 입력 상태와 경과 시간은 tick 분할과 프레임률에 관계없이 같은 결과를 만든다.
- 수치와 콘텐츠는 장면이 아니라 도메인과 `game/content/`가 소유한다.

## 핵심 순환

```text
주간 정비
  → 방치 수입 수령
  → 실패 보고서와 병목 확인
  → 요원 강화·패치 비교
  → 야간근무 시작
  → 9개 일반 웨이브 + 보스
  → 근무 결과·별·급여·해금
  → 주간 정비에서 재도전 또는 다음 야간
  → 둘째 야간 ★★★ 뒤 자발적 버전 업데이트
```

한 버전은 두 번의 야간근무로 구성한다. 첫째 야간 ★★★는 둘째 야간을, 둘째 야간 ★★★는
주간의 버전 업데이트를 연다. 각 야간의 전투 시계는 최대 75초이며 보통 완주 체감은
시작·경고를 포함해 60~80초를 목표로 한다.

## 제품 단계

| 단계 | 플레이어가 하는 일 | 자동 진행 |
|---|---|---|
| `DAY_PREP` | 수입 수령, 보고서 확인, 강화, 패치 비교·편성, 다음 근무 시작 | 전투 없음 |
| `NIGHT_ACTIVE` | 전투와 위험을 관찰, 필요한 경우 설정에서 일시정지 | 공격, 이동, 침입, 보스 행동과 QA 구조 |
| `SHIFT_RESULT` | 별·급여·해금·실패 근거를 확인하고 주간으로 이동 | 결과 재계산 없음 |
| `VERSION_UPDATE` | 초기화·보존 목록 확인 뒤 실행 또는 취소 | 원자적 변경·저장 |

설정 또는 접근성 모달이 야간에 열리면 전투를 완전히 멈춘다. 주간과 결과에서는 배경 전투를
돌리지 않는다.

## 야간 자동 디펜스

### 일반 웨이브

- 웨이브 1~9의 최대 처리시간은 각각 5초다.
- 적을 모두 처리하면 0.4초의 실시간 전환 뒤 다음 웨이브를 자동 시작한다.
- 5초에 살아 있는 적은 서버에 침입하고 해당 웨이브에서 제거된다.
- 서버 안정도는 100이며 적의 침입 피해는 등급에 따라 5/10/20이다.
- 한 웨이브의 침입 피해는 최대 40이다.
- 안정도가 0이 된 웨이브는 완료로 세지 않고 즉시 근무를 끝낸다.
- 일반 적은 요원을 공격하지 않는다.

### 보스 웨이브

- 웨이브 9 뒤에는 0.4초 전환 대신 1초 보스 경고를 사용한다.
- 웨이브 10은 30초 제한시간의 `Watchdog Process` 보스전이다.
- 보스전에서만 요원 HP, 역할, `PROCESS DOWN`과 QA 자동 구조를 활성화한다.
- 보스 처치가 성공이고, 30초 시간 초과 또는 전원 DOWN은 실패다.
- 제한시각과 같은 시각의 예약된 공격을 먼저 처리하므로 정확히 30초의 처치는 성공이다.

처음 보는 근무는 1배속으로 진행한다. 해당 근무를 ★★★로 완료한 뒤 같은 근무를 재도전할
때만 2배속을 사용할 수 있으며 결과는 1배속과 같아야 한다.

상세 웨이브 편성, 판정 순서, 표시 사건과 검증 기준은
[Product V2 혼합 디펜스 전투 명세](COMBAT_HYBRID_SPEC.md)를 따른다.

## 별과 근무 결과

| 완료 웨이브 | 평가 | 의미 |
|---:|---|---|
| 0~2 | 별 없음 | 30% 미만 방어 |
| 3~5 | ★ | 30% 이상 방어 |
| 6~9 | ★★ | 60% 이상 방어 |
| 10 | ★★★ | 보스까지 완전 방어 |

남은 안정도는 별을 바꾸지 않고 서버 무결성 급여에만 반영한다. 성공과 실패는 읽기 전용
결과를 정확히 한 번 만들며, 결과를 다시 열어도 비트·별·해금을 다시 지급하지 않는다.

## 요원

| ID | 표시 이름 | 역할 | 보스 능력 | Product V2 최초 해금 |
|---|---|---|---|---|
| `debugger` | 디버거 | 전열 안정화 | 높은 위협도와 피해 감소로 팀의 공격을 대신 받음 | 시작 |
| `build_engineer` | 빌드 엔지니어 | 보스 화력 | 보스 대상 피해 증가 | 시작 |
| `sprite_artist` | 스프라이트 장인 | 팀 템포 | 가동 중 전원 공격 주기 단축 | 첫째 야간 ★ |
| `qa_imp` | QA 임프 | 자동 복구 | 첫 DOWN 요원 1회 자동 구조 | 첫째 야간 ★★ |

요원 공격과 QA 구조는 자동이다. 비트로 개별 요원 레벨을 올리고 모든 증가량·HP·피해량은
소수점을 버린 정수로 표시한다. 처음부터 잠긴 요원과 정확한 해금 조건·진행도를 보여준다.

## 임시 패치

후보는 기존 5개, 동시 장착 슬롯은 최대 3개다. 새 패치는 추가하지 않는다. 찬 슬롯에서
새 패치 장착은 즉시 교체이며 슬롯 비우기는 장착 패치가 있을 때만 보이는 보조 행동이다.

| ID | 패치 | 장점 | 부작용 | Product V2 최초 해금 |
|---|---|---|---|---|
| `frame_skip` | 애니메이션 프레임 생략 | 공격 속도 +35% | 비트 획득 -20% | 첫째 야간 ★ |
| `unsafe_build` | 검증 단계 생략 | 전체 피해 +45% | 보스 회복 효과 +25% | 첫째 야간 웨이브 5 완료 |
| `reward_bypass` | 보상 테이블 우회 | 비트 획득 +50% | 적 최대 체력 +20% | 첫째 야간 웨이브 7 완료 |
| `rollback_lock` | 롤백 잠금 | 보스 회복 효과 -70% | 전체 피해 -15% | 첫째 야간 웨이브 9 완료 |
| `safe_mode` | 저사양 안전 모드 | 보스 특수 행동 간격 +40% | 비트 획득 -25% | 둘째 야간 보스 최초 조우 |

패치 슬롯은 첫째 야간 ★, 첫째 야간 ★★★, 둘째 야간 ★★에서 순서대로 열린다. 해금은
근무 결과에서 한 번만 정산하고 다음 주간부터 사용한다. 여러 해금이 동시에 발생해도 연속
모달을 띄우지 않고 결과 요약과 주간 패치 보드의 `새 패치` 배지로 묶는다.

패치 화면은 장착 전에 다음 정보를 한 화면에서 비교한다.

- 장착·교체 가능 여부와 비용
- 변경 전·후 예상 처치 시간
- 변경 전·후 예상 침입 수와 보스 위험
- 변경 전·후 비트 획득 배율
- 한 줄 장점과 부작용

## 진단과 현장 보고서

진단은 정답 행동을 명령하지 않고 실제 시뮬레이션 근거를 제공한다.

- 일반전: 예상 미처리 적, 예상 침입 피해와 서버 안정도
- 보스전: 예상 처치 시간, 예상 DOWN 수, 보스 복구량과 QA 구조 상태
- 경제: 다음 강화까지 필요한 비트와 선택한 패치의 수입 비용

실패 결과는 가장 큰 원인 하나와 다음에 비교할 지표 또는 대응 범주 하나를 먼저 보여준다.
특정 강화·패치를 정답처럼 명령하지 않는다. 역할이 다른 요원의 사실 기반 보고는 최대
2행으로 제공한다. 새 보고서는 아이콘으로 알리고 열람 뒤에도 같은 아이콘으로 다시 볼 수
있다. 보고서는 독립 읽기 전용 모달이며 강화·패치 명령이나 숨은 보너스를 실행하지 않는다.

## 재화와 주간 방치

### 비트

한 버전 안에서 요원 강화와 패치 교체에 쓰는 정수 재화다. 첫 버전과 새 버전은 30비트로
시작한다.

```text
근무 지급 = 기본급 12
          + floor(
              (완료 웨이브 × 3 + 보스 처치 6 + 서버 무결성 보너스 최대 10)
              × 장착 패치의 비트 배율
            )
          + 새로 통과한 별의 최초 보상
```

별 최초 보상은 ★ +12, ★★ 추가 +18, ★★★ 추가 +30이다. 즉시 포기에는 기본급을 지급하지
않고 성공·실패 결과가 처음 생성될 때만 지급한다.

### 주간 방치

- `DAY_PREP`에서만 20분마다 1비트를 쌓는다.
- 최대 12시간·36비트까지 누적한다.
- 야간과 결과에서는 시간을 저장한 채 진행을 멈춘다.
- 오프라인으로 전투, 별, 해금, 패치 선택과 버전 업데이트를 수행하지 않는다.
- 수입을 적용하고 저장한 뒤 읽기 전용 인수인계를 표시하며 같은 부재를 두 번 적용하지 않는다.

### 패치노트와 레거시 빌드 캐시

둘째 야간 ★★★ 뒤 버전 업데이트를 실행하면 패치노트 1개를 받는다. 패치노트 1개는 기존
`레거시 빌드 캐시` 영구 보너스 1레벨을 사는 데 사용한다. Product V2에서는 새 영구 성장
종류를 추가하지 않는다.

## 버전 업데이트

- 주간에서만 사용자가 선택해 실행한다.
- 초기화: 비트는 30으로 교체, 요원 레벨, 장착 패치, 현재 버전의 야간 진행·별·최초
  보상, 재도전 2배속, 전투 상태, 마지막 결과와 현장 보고서 key·행·읽음 상태.
- 보존: 패치노트, 회차 수, 발견한 요원·패치, 열린 슬롯, 레거시 빌드 캐시, 설정,
  접근성, 스토리·도움말 확인 기록.
- 별과 최초 보상 기록은 `버전 번호 + 야간 번호`로 구분해 새 버전에서 다시 달성할 수 있다.
- 초기화·보존 항목을 확인창에 표시하고 원자적 세션 변경과 저장에 성공한 뒤에만 완료
  보고서를 연다.

## 앱 진입과 복귀

- 첫 실행은 타이틀과 프롤로그 뒤 최초 저장에 성공하면 첫 `DAY_PREP`에 들어간다.
- 완전 재실행은 현재 주간·야간·결과 상태를 요약하는 진입 화면을 거쳐 정확한 저장 상태로
  돌아간다.
- 짧은 앱 전환은 마지막 화면과 탭을 복원한다.
- 야간에서 앱을 벗어나면 전투를 진행하지 않고 정확한 하위 상태와 남은 시간에서 재개한다.
- 저장 손상, 최신 schema와 쓰기 실패를 조용한 초기화로 숨기지 않는다.

화면 문구, 저장·복구와 수명주기 계약은 Product V2 전환표가 추가된
[앱 셸·Product V2 수명주기 명세](APP_SHELL_SPEC.md)를 따른다.

## 플레이테스트 성공 기준

- 5명 중 4명이 첫 야간 뒤 지킬 대상, 종료 이유와 다음 행동을 설명한다.
- 5명 중 4명이 적 HP와 남은 시간을 서로 바꾸어 설명하지 않는다.
- 모든 직접 피해에서 발사·도착·피격과 HP 감소를 눈으로 연결할 수 있다.
- 첫 0성 실패 또는 누적 급여 뒤 강화로 최소 한 웨이브 이상 전진한다.
- 5명 중 4명이 패치 하나의 이점과 비용을 같은 화면에서 설명한다.
- 버전당 두 근무와 주간 정비가 강제 대기 없이 이어진다.
- 5명 중 3명 이상이 야간에 `할 일이 없다`고 답할 때만 중간 관제 지시를 별도 A/B
