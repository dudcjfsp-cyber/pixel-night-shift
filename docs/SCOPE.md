# Product V2 수직 슬라이스 범위

## 문서 상태

- 상태: 현재 개발 마일스톤
- 제품 기준: [Product V2 계획표](PRODUCT_V2_PLAN.md)
- 전투 기준: [Product V2 혼합 디펜스 전투 명세](COMBAT_HYBRID_SPEC.md)
- 앱 기반: [앱 셸·Product V2 수명주기 명세](APP_SHELL_SPEC.md)

최초 20스테이지 회색상자와 현재 배포 본편 V1은 완료된 기준선이다. V1 상세값은
[V1 전투 동결 기준선](V1_COMBAT_BASELINE.md)에 보존한다. Product V2는 그 앱 셸과
콘텐츠를 보존하면서 전투 순환을 `주간 방치 정비 → 야간 자동 디펜스 → 근무 결과`로
교체한다.

## 세대 구분

| 이름 | 범위와 상태 |
|---|---|
| 최초 회색상자 | 20스테이지, 단순 자동 전투, 저장·오프라인 이전의 완료된 역사 기준 |
| 현재 본편 V1 | 20스테이지, 25초 보스, 유지보수·자동 재도전, schema 2를 사용하는 현재 배포 구현 |
| Legacy Combat V2 | 일반 적 공격·6초 복구·긴급 재배포를 비교한 격리 실험 |
| Product V2 | 버전당 야간 2회, 각 9+1웨이브, 주간 방치와 결과 화면을 사용하는 현재 목표 |
| Defense Lab | Product V2 전투를 본편 승격 전에 검증하는 격리 프로토타입 |

Defense Lab이 완료 기준을 통과하기 전에는 현재 본편의 기본 실행 경로와 저장 schema를
바꾸지 않는다. 통과 뒤에는 Product V2를 유일한 권위 `GameSession`으로 승격하고 중복
전투 분기를 정리한다.

## 목표

이번 단계의 목표는 콘텐츠 양을 늘리는 것이 아니라 다음 가설을 검증하고 제품화하는 것이다.

> 짧은 자동 디펜스의 실패 원인을 읽고 주간에 요원·패치를 고친 뒤 즉시 재도전하는 순환이
> 기존의 끝없는 자동 전투보다 목표와 판단을 분명하게 만드는가?

## 포함

### 제품 순환

- `DAY_PREP`, `NIGHT_ACTIVE`, `SHIFT_RESULT`, 주간 전용 `VERSION_UPDATE`
- 버전당 야간근무 2회
- 일반 9웨이브 × 최대 5초와 보스 1웨이브 × 30초
- 조기 전멸 0.4초 자동 진행
- 서버 안정도, 침입, 3/6/10 완료 별
- 실패 뒤 결과를 거쳐 같은 주간에서 무료 복구·수동 재도전
- 첫 완료 뒤 해당 야간 재도전에서만 2배속

### 기존 콘텐츠 재사용

- 고정 위치의 기존 요원 4명과 보스 전용 역할·HP·DOWN·QA 구조
- 기존 패치 5개와 최대 슬롯 3개
- 기존 적·보스·서버실 픽셀 에셋과 오디오
- 기존 패치노트와 레거시 빌드 캐시
- 기존 타이틀, 프롤로그, 설정과 안전 영역

### 주간 성장

- 주간 방치 수입 20분당 1비트, 최대 12시간·36비트
- 정수 비트 급여와 별 최초 보상
- 네 요원의 한 화면 선택과 강화
- 패치 장착 전후 예상 처치시간·침입·보스 위험·수입 비교
- 잠긴 요원·패치·슬롯의 정확한 조건과 진행도
- 사실 기반 최신 실패 보고서
- 주간에서 사용자가 선택하는 버전 업데이트

### 기술 기반

- Godot 4.7과 typed GDScript
- 논리 해상도 `360×640`의 세로형 반응형 Web 빌드
- `AppRoot → GameSession → domain/content` 의존 방향
- 결정론적 야간 전투와 콘텐츠 경계 검증
- 원자적 로컬 저장·백업·복구
- schema 1·2에서 schema 3으로의 명시적 원자적 전환
- Web·desktop·모바일 포커스 이탈과 복귀의 단일 수명주기 경로
- GitHub Pages 테스트 배포

## 구현 단계

1. Product V2 권위 문서와 세대 구분 확정
2. 격리된 야간 도메인·콘텐츠 구현
3. Defense Lab 회색상자와 전투 가독성 검증
4. 주간·야간·결과 제품 순환 연결
5. 주간 방치 메타·경제·해금 연결
6. Product V2 본편 승격과 schema 3
7. 외부 피드백 폴리시, 반응형 E2E와 테스트 배포

각 단계는 앞 단계 완료 기준을 통과한 뒤 진행하고 자연스러운 구현 경계에서 커밋한다.
모든 UI 변형이나 내부 호출 순서를 위한 테스트 코드는 만들지 않는다.

## 완료 조건

- 첫 실행부터 `DAY_PREP → NIGHT_ACTIVE → SHIFT_RESULT → DAY_PREP`를 막힘 없이 경험한다.
- 한 야간은 일반 9웨이브와 보스 1웨이브로 종료되고 자동 재도전하지 않는다.
- 같은 초기 상태와 같은 경과시간은 tick 분할과 배속에 관계없이 같은 결과를 만든다.
- 정확히 5초·30초의 공격 우선 판정, 침입 상한 40과 3/6/10 별이 재현된다.
- 첫 0성 실패 또는 누적 급여 뒤 강화로 최소 한 웨이브 이상 전진할 수 있다.
- 실패 결과·별·급여·해금과 오프라인 수입을 같은 상태에서 두 번 지급할 수 없다.
- 야간 이탈은 전투를 진행하지 않고 정확한 하위 상태에서 재개한다.
- 주간 방치만 최대 12시간까지 비트를 만들고 전투·패치·버전 업데이트를 대신하지 않는다.
- 버전 업데이트의 초기화·보존 목록이 실행 전에 보이고 성공한 저장 뒤에만 완료된다.
- schema 1·2 전환 실패가 활성 세션이나 기존 저장을 부분 변경하지 않는다.
- 360×640과 긴 Galaxy 화면에서 주요 터치 영역, 설정, 보고서와 전투 HUD가 잘리지 않는다.
- 외부 테스트 5명 중 4명이 지킬 대상, 종료 이유와 다음 행동을 설명한다.
- 자동 테스트와 headless 프로젝트 시작이 통과한다.

## 범위 밖

- 신규 요원, 패치, 적, 보스, 야간, 버전과 지역 콘텐츠
- 맵, 길찾기, 사거리와 타워 배치가 있는 정통 타워디펜스
- 수동 공격, 수동 타기팅, 액티브 스킬, 회피와 반복 탭
- 실시간 패치 교체와 기본 규칙의 중간 관제 지시
- 모집, 영입권, 부서, 사건, 장비, 인벤토리와 여러 재화
- 일일 보상, 우편, 업적, 랭킹과 라이브 이벤트
- 광고, 결제, 분석, 계정, 서버, 네트워크와 클라우드 저장
- Android 네이티브 패키징과 스토어 배포
- 본편 승격 전 진행하는 대규모 아트·오디오 확장
- 검증 뒤에도 V1·Legacy·Product V2 전투 엔진을 영구 병행하는 구조

제외 항목은 빈 서비스, 가짜 버튼, 선행 데이터 구조로 미리 만들지 않는다.

## 범위 변경 규칙

- 신규 콘텐츠나 시스템을 추가하려면 비슷한 구현·검증 비용의 항목을 빼거나 다음
  마일스톤으로 명시적으로 이동한다.
- 새로운 외부 의존성, 공개 API, 데이터 마이그레이션 방식과 배포 대상 변경은 별도 승인
  없이 도입하지 않는다.
- Defense Lab 완료 전에는 본편 실행 경로, `GameSession`, `AppRoot`와 저장 schema를
  변경하지 않는다.
- 실제 외부 테스트 5명 중 3명 이상이 야간에 `할 일이 없다`고 답하기 전에는 중간 관제
  지시를 Product V2 기본 규칙에 넣지 않는다.
