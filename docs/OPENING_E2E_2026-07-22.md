# 오프닝 E2E 확인 · 2026-07-22

## 결과

- 상태: 실제 렌더링 E2E 통과
- 해상도: `360×640`
- 엔진: Godot `4.7.stable`
- 렌더러: OpenGL 3.3 Compatibility · NVIDIA GeForce GTX 1660
- 저장·설정: `.godot/manual-e2e-runtime/` 아래 격리

새 근무의 타이틀부터 인게임까지 연결되고, 저장된 근무를 다시 불러와 이어하기로 운영실에 진입하는 경로를 확인했습니다.

## 확인 경로

| 순서 | 상태 | 결과 |
|---|---|---|
| 1 | 빈 기록 → 타이틀 `게임 시작` | 활성 세션 없이 표시됨 |
| 2 | 프롤로그 1~5 | 각 단계에서 활성 세션과 조기 저장 없음 |
| 3 | `근무 인계받기` | 최초 저장 뒤 현장·온보딩 진입 |
| 4 | 온보딩 건너뛰기 | 실제 자동 전투 화면 표시 |
| 5 | 운영실 이동 | 같은 세션으로 운영실 진입·저장 |
| 6 | AppRoot 재생성 | 타이틀 `이어하기`, 세션은 아직 비활성 |
| 7 | `이어하기` | 저장 세션 활성화 뒤 운영실 진입 |

제품 버튼의 실제 화면 좌표에 마우스 이동·누름·뗌 이벤트를 주입했으며, 각 전환 뒤 상태를 단언하고 화면을 저장했습니다. 최종 캡처 11장은 로컬의 `.godot/manual-e2e-captures/opening-20260722-02/`에 있습니다.

## 시각 검토와 수정

- 프롤로그 2·3컷의 적·요원을 위로 옮겨 상태띠가 캐릭터 발을 가리지 않게 했습니다.
- 프롤로그 4컷 본문을 짧게 다듬어 마지막 글자만 다음 줄로 떨어지지 않게 했습니다.
- 타이틀 신규·이어하기, 프롤로그 5컷, 온보딩, 인게임, 운영실은 잘림이나 조작 영역 겹침 없이 표시됐습니다.

## 수동 실행

새 세션 ID는 빈 기록으로 시작합니다. 같은 ID를 다시 실행하면 그 테스트 기록을 이어갑니다.

```powershell
.\tools\run_godot_manual_e2e.ps1 -SessionId opening-check-001
```

이 실행기는 실제 `user://`와 설정을 건드리지 않고 Godot 네이티브 종료 오류 대화상자를 억제합니다.

## 남은 사람 확인

Windows Computer Use가 Godot 창 캡처에서 `SetIsBorderRequired failed (0x80004002)`를 반환해 외부 도구로 직접 누르는 방식은 수행하지 못했습니다. 따라서 이번 결과는 실제 렌더러·포인터 이벤트 E2E와 사람이 캡처를 검토한 결과이며, 사람 손으로 클릭하며 음악 전환과 체감 속도를 듣는 최종 감각 검증은 별도로 남습니다.

오디오 파일 18개의 구조·경로 검증은 통과했지만, 이번 도구 환경에서는 주관적인 청음 평가를 대신하지 않습니다. Godot 웹 내보내기 뒤에는 브라우저 자동재생, 로컬 저장, 세로 화면을 다시 확인해야 합니다.
