## 2. 제품 V2 한 문장 정의

> 낮에는 방치 수입으로 요원과 패치를 정비하고, 밤에는 최대 네 요원이 10웨이브 동안 낡은

### 대상 플레이어

- 개발 지식이 없어도 목표와 결과를 이해할 수 있는 일반 플레이어가 1차 대상이다.
- 개발·서버 소재는 알아보면 더 재미있는 2차 풍미로 사용한다.
- 쉬운 기능명을 먼저 표시하고 전문용어는 부제, 보고서와 도움말에서 보충한다.

### 유지할 제품 원칙

- Godot 4.7, 세로형 논리 해상도 360×640과 웹 배포를 유지한다.
- 공격, 타기팅과 QA 구조는 자동으로 진행한다.
- 플레이어는 직접 공격하거나 타워를 배치하지 않는다.
- 플레이어의 핵심 행동은 관찰, 진단, 요원 강화, 패치 선택과 버전 업데이트이다.
- 특정 참고 작품의 캐릭터, 명칭, 대사, 화면 구성과 이야기 전개를 재현하지 않는다.

## 5. 목표 제품 순환

수직 슬라이스의 한 버전은 우선 두 번의 야간근무로 구성한다.

```text
타이틀·프롤로그
      ↓
주간 정비
      ↓
첫째 야간근무: 기존 1~10단계 재구성
      ↓ 성공·실패
근무 결과 → 주간 정비 → 재도전 또는 둘째 야간근무
                              ↓
둘째 야간근무: 기존 11~20단계 재구성
                              ↓ 성공·실패
근무 결과 → 주간 정비 → 재도전 또는 버전 업데이트
```

- 첫째 야간의 ★★★는 둘째 야간을 해금한다.
- 둘째 야간의 ★★★는 주간의 버전 업데이트 선택을 해금한다.
- 각 야간의 별과 최초 보상은 따로 기록한다.
- 버전 업데이트는 자동 실행하지 않고 주간에 사용자가 선택한다.
- 버전당 야간근무 2회는 Product V2의 기준값이다. 콘텐츠 확장은 이 순환의 이해도와
  재도전성이 검증된 뒤 별도 마일스톤에서 결정한다.

## 6. 야간근무 규칙

### 일반 웨이브

- 야간 시작 전 2초 카운트다운을 표시한다. 이 시간에는 전투 시계를 진행하지 않는다.
- 웨이브 1~9는 각각 최대 5초 안에 처리한다.
- 웨이브 시작 시 적 무리가 단일 진입로로 서버 코어를 향한다.
- 적을 모두 처리하면 0.4초의 짧은 전환 뒤 다음 웨이브를 자동 시작한다.
- 5초 경계까지 남은 적은 각자의 침입 피해를 주고 해당 웨이브에서 제거된다.
- 서버 안정도가 남아 있으면 다음 웨이브를 시작한다.
- 일반 적은 요원을 공격하지 않는다.
- 야간 도중 수동 웨이브 호출, 강화, 패치 교체와 선택 팝업을 표시하지 않는다.

### 서버 안정도와 침입

| 항목 | Defense Lab 초기값 |
|---|---:|
| 최대·야간 시작 안정도 | 100 |
| 소형 적 침입 피해 | 5 |
| 일반 적 침입 피해 | 10 |
| 급증 적 침입 피해 | 20 |
| 한 웨이브 침입 피해 상한 | 40 |
| 위험 경고 시작 | 안정도 40 이하 또는 다음 침입 예상 피해가 현재 안정도 이상 |
| 주간 복구 | 다음 근무 전 무료로 100까지 전량 복구 |

- 침입 피해는 살아남은 적별로 합산하되 한 웨이브에서 최대 40까지만 적용한다.
- 안정도가 0이 되면 즉시 근무를 끝내며 그 웨이브는 완료 웨이브로 세지 않는다.
- 서버 침입은 생존 적을 한 묶음으로 처리해 `적의 코어 도달 → 코어 점멸·짧은 충격 →
  안정도 감소` 순서로 보여준다. 상한이 적용되면 `안정도 -40 · 웨이브 피해 상한`을
  표시해 코어에 닿았는데 수치가 변하지 않는 적을 만들지 않는다.

### 일반 웨이브 초기 편성

| 웨이브 | 적 수·침입 등급 | HP 배율 | 학습·위험 신호 |
|---:|---|---:|---|
| 1 | 일반 3 | ×1.00 | 이동·피격·침입 규칙 학습 |
| 2 | 일반 3 | ×1.00 | 첫 반복으로 규칙 확인 |
| 3 | 일반 4 | ×1.00 | 첫 별 경계. 완전히 무너지면 0성 실패 가능 |
| 4 | 일반 4 | ×1.25 | HP 증가 |
| 5 | 일반 3 + 급증 1 | ×1.25 | `트래픽 급증` 사전 경고, 선택창 없음 |
| 6 | 일반 5 | ×1.25 | 두 번째 별 경계 |
| 7 | 일반 5 | ×1.55 | 후반 압박 |
| 8 | 일반 6 | ×1.55 | 후반 압박 |
| 9 | 일반 6 | ×1.55 | 보스 접근 경고 |

적 수, HP 배율, 개별 침입 피해는 콘텐츠 파일에 두되 표의 구조를 첫 회색상자 기준으로
사용한다. 첫 시도 시작 요원 2명으로 ★는 안정적으로, ★★는 합리적으로, ★★★도 초기
강화 배분이 정확했다면 강제 실패 없이 달성할 수 있어야 한다.

### 보스 웨이브

- 웨이브 9를 완료하면 0.4초 전환 대신 전투 시계를 멈춘 1초 보스 경고를 표시한다.
- 웨이브 10은 30초 제한시간의 보스전이다.
- 기존 요원 HP, 역할, PROCESS DOWN과 QA 자동 구조를 활성화한다.
- 보스 처치 시 해당 야간근무에 성공한다.
- 30초 초과 또는 전원 DOWN 시 해당 야간근무에 실패한다.

### 판정 순서, 배속과 저장

- 제한시각과 같은 시각에 예약된 공격·피격을 먼저 처리한 뒤 생존 적의 침입 또는 보스
  시간초과를 판정한다.
- 시작 대기, 웨이브 전환과 보스 경고는 저장 가능한 전투 하위 상태로 관리한다. 저장에는
  하위 상태와 남은 시간을 포함하고 오프라인에서는 진행하지 않는다.
- 2배속은 현실시간 대비 전투 시뮬레이션 시간의 진행률만 바꾸며 같은 입력 상태의 결과를
  바꾸지 않는다. 시작 카운트다운, 0.4초 웨이브 전환과 보스 경고는 배속하지 않는
  실시간 표시 구간으로 둔다.
- 2배속 버튼은 해당 야간의 ★★★ 기록 전에는 잠금 조건을 표시하고, 해금 뒤에도 기본값은
  1배속이다.
- 설정과 접근성 모달을 열면 야간을 완전히 일시정지한다.

### 야간 종료

- 서버 안정도 0
- 보스 제한시간 30초 초과
- 보스전 요원 전원 DOWN
- 보스 처치

성공과 실패는 반드시 읽기 전용 근무 결과를 만든 뒤 주간으로 전환한다. 현재 본편의 자동
유지보수 파밍과 자동 보스 재도전은 Product V2에서 제거한다.

### 별과 완료율

| 완료 웨이브 | 평가 | 의미 |
|---:|---|---|
| 0~2 | 별 없음 | 첫 보상 전에도 반복 급여와 주간 방치로 복구 가능해야 한다. |
| 3~5 | ★ | 30% 이상 방어 |
| 6~9 | ★★ | 60% 이상 방어 |
| 10 | ★★★ | 보스까지 완전 방어 |

남은 안정도는 별 조건을 바꾸지 않는다. 대신 근무 급여의 `서버 무결성 보너스`로만
반영해 완벽 방어를 보상하되 별 목표를 흐리지 않는다.

### 시간 밸런스 원칙

- 웨이브 시간은 버전마다 길어지는 난이도 수단이 아니라 플레이 리듬의 고정 기준으로 쓴다.
- 5초는 강제로 기다리는 간격이 아니라 적을 처리할 수 있는 최대 시간이다.
- 난이도는 적 수, 총 HP, 침입 피해, 보스 행동과 요원 가동률로 조절한다.
- 첫 회색상자에서 일반 적 총 HP는 기준 유효 DPS의 약 3.5~4초분, 보스 HP는 약
  22~25초분을 시작점으로 삼고 실제 시뮬레이션 결과로 조정한다.
- 기존 약 20분 진행을 전제로 한 성장·해금 수치를 75초 야간에 그대로 사용하지 않는다.

### 전투 가독성 기준

- 직접 피해는 `투사체 도착 → 약 0.1초 피격 점멸·미세 반동 → HP와 피해 수치 갱신`
  순서로 표시한다.
- 같은 적에게 빠르게 들어오는 피해 숫자는 약 0.25초 단위로 합쳐 화면 도배를 막는다.
- HP는 적 가까이의 막대와 정수로, 제한시간은 상단의 시계 아이콘과 다른 색으로 표시한다.
- 진행 HUD는 10칸을 사용하고 3·6에는 별, 10에는 보스 표식을 둔다. 다음 웨이브의 쉬운
  특성명과 아이콘을 한 칸 미리 보여준다.
- 화면 흔들림은 일반 공격에는 쓰지 않는다. 코어 침입은 60~80ms, 보스 특수 충격은
  100~140ms만 사용하며 설정에서 끌 수 있게 한다.

## 7. 주간근무와 경제

### 주간에서 할 일

- 직전 근무의 정산과 실패 보고서 확인
- 서버 안정도와 요원 전원 무료 복구
- 방치 수입 수령
- 네 요원 확인과 강화
- 패치 전후 비교와 편성
- 잠긴 슬롯의 조건과 진행도 확인
- 다음 야간근무 또는 재도전 시작
- 조건을 만족했다면 버전 업데이트 선택

주간은 에너지 충전을 기다리는 입장 제한이 아니다. 준비가 끝나면 즉시 다음 야간을 시작할
수 있다.

### 재화와 보상 역할

| 요소 | Product V2 역할 |
|---|---|
| 비트 | 요원 강화와 패치 비용. 같은 버전의 야간근무 사이에는 유지하고 버전 업데이트 시 초기화한다. |
| 패치노트 | 버전을 넘어 유지되는 영구 성장 재화. 버전 업데이트 실행 시 1개 지급한다. |
| 별 | 소비 재화가 아닌 근무별 최고 성과와 최초 보상 수령 기록이다. |
| 반복 근무 급여 | 별 갱신 여부와 무관하게 처치·완료 웨이브에 따라 비트를 지급해 소프트락을 막는다. |
| 주간 방치 수입 | 실패 복구를 돕는 작고 예측 가능한 비트 수입이다. 야간 보상보다 작아야 한다. |

### 근무 보상 기준표

| 보상 | 지급 기준 | 비트 |
|---|---|---:|
| 첫 버전 준비금 | 새 게임의 첫 `DAY_PREP` 생성 | 30 |
| 기본급 | 즉시 포기가 아닌 성공·실패 결과가 최초 생성될 때 | 12 |
| 완료 급여 | 완료 웨이브마다 | +3 |
| 보스 처치 | 웨이브 10 보스 처치 | +6 |
| 서버 무결성 | 결과 시 남은 안정도 20%마다 내림 계산 | +2, 최대 +10 |
| ★ 최초 | 해당 근무에서 처음 3웨이브 완료 | +12 |
| ★★ 최초 | 해당 근무에서 처음 6웨이브 완료 | 추가 +18 |
| ★★★ 최초 | 해당 근무에서 처음 보스 처치 | 추가 +30 |
| 주간 방치 | `DAY_PREP`에서 경과한 시간 | 20분마다 1, 최대 12시간·36 |
| 버전 업데이트 | 사용자가 주간에서 실행 | 패치노트 +1, 다음 버전 준비금 30 |

반복 근무 급여는 다음 식을 사용한다.

```text
근무 급여 = 기본급 12
          + floor(
              (완료 웨이브 × 3 + 보스 처치 6 + 서버 무결성 보너스 최대 10)
              × 장착 패치의 비트 배율
            )
          + 새로 통과한 별의 최초 보상
```

- 비트 배율 패치를 적용하지 않은 기준 완전 클리어 반복 급여는 최대 58비트이다.
- 비트 배율 패치를 적용하지 않고 한 근무의 ★★★를 처음 달성하면 별 최초 보상 누계 60을
  포함해 최대 118비트이다.
- 첫 버전과 새 버전은 30비트로 시작한다. 시작 요원 두 명의 첫 강화비 12+15를 감당하지만
  모든 요원을 한꺼번에 키울 수는 없는 값이다. 버전 업데이트 전의 남은 비트는 이월하지
  않는다.
- 이전 등급을 건너뛰어 처음 ★★나 ★★★를 달성하면 새로 통과한 하위 등급의 최초
  보상도 같은 정산에서 함께 지급한다.
- 첫 별이 없는 실제 패배도 최소 12비트이며, 완료한 웨이브가 있으면 15~18비트가 된다.
  첫 실패 급여 또는 누적 급여로 다음 초기 강화를 할 수 있어야 한다.
- `근무 포기`가 필요해지더라도 기본급을 지급하지 않는다. 자동 결과 중복 생성과 포기
  반복으로 비트를 얻을 수 없어야 한다.
- 비트 획득 배율 패치는 완료 급여, 보스 처치와 서버 무결성 보너스의 합계에 곱한 뒤
  마지막에 한 번 내림한다. 기본급, 최초 별 보상과 주간 방치에는 적용하지 않으며 모든
  지급·비용·표시는 정수만 사용한다.
- 12시간 주간 방치 최대 36비트는 배율 패치가 없는 완전 클리어 반복 급여 58보다 작다.
  비트 감소 패치를 선택하면 직접 완주 급여가 36보다 낮아질 수 있으며 이는 방어력과
  수입을 맞바꾸는 명시적 비용으로 취급한다. 오프라인으로 별, 웨이브 완료, 요원과 패치를
  자동 획득하지 않는다.

수치는 장르 조사를 바탕으로 정한 Defense Lab 시작값이다. 플레이테스트에서는 `첫 0성
실패 또는 누적 급여로 강화한 뒤 최소 한 웨이브 전진`, `배율 패치 없는 완주 반복 급여가
방치 최대치보다 큼`, `첫 ★★★ 뒤 여러 강화 선택지가 생김`을 만족하는 범위 안에서만
조정한다.

### 요원·패치·슬롯 해금표

잠긴 항목은 처음부터 보이게 하고 `첫째 야간 6웨이브 완료 · 현재 4/6`처럼 정확한 조건과
현재 진행도를 표시한다. 해금은 근무 도중 팝업을 띄우지 않고 결과 정산에 한 번만 기록한
뒤 다음 주간부터 사용할 수 있다.

| 조건 | 해금 |
|---|---|
| 새 게임 시작 | 디버거, 빌드 엔지니어. 패치 슬롯 0개 |
| 첫째 야간 ★ | 스프라이트 장인, 패치 슬롯 1, `애니메이션 프레임 생략` |
| 첫째 야간 웨이브 5 완료 | `검증 단계 생략` |
| 첫째 야간 ★★ | QA 임프 |
| 첫째 야간 웨이브 7 완료 | `보상 테이블 우회` |
| 첫째 야간 웨이브 9 완료 | `롤백 잠금` |
| 첫째 야간 ★★★ | 패치 슬롯 2, 둘째 야간, 첫째 야간 재도전 2배속 |
| 둘째 야간 보스 최초 조우 | `저사양 안전 모드` |
| 둘째 야간 ★★ | 패치 슬롯 3 |
| 둘째 야간 ★★★ | 주간 버전 업데이트, 둘째 야간 재도전 2배속 |

첫 시도에 여러 조건을 한꺼번에 달성해도 연속 모달을 띄우지 않는다. 결과 화면에는
`신규 요원`, `다음 근무`, `새 시스템`의 세 묶음까지만 요약하고 새 패치는 주간 패치
보드의 배지와 전후 비교에서 확인하게 한다.

### 버전 업데이트의 초기화와 보존

버전 업데이트는 둘째 야간 ★★★ 뒤 주간에서만 사용자가 실행한다. 별과 최초 보상 기록은
`버전 번호 + 야간 번호`로 구분해 새 버전에서 다시 달성하고 받을 수 있게 한다.

| 초기화·새로 생성 | 다음 버전에도 보존 |
|---|---|
| 비트는 준비금 30으로 교체 | 패치노트와 회차 수 |
| 모든 요원 레벨 | 발견한 요원과 패치 |
| 장착 패치 | 해금한 패치 슬롯 |
| 해당 버전의 두 야간 진행·별·최초 보상 | 레거시 빌드 캐시 |
| 해당 버전 야간의 재도전 2배속 | 설정과 접근성 값 |
| 서버·요원 전투 상태와 마지막 결과 | 스토리·도움말 확인 기록 |

- 새 버전은 첫째 야간부터 시작하며 둘째 야간과 각 재도전 2배속은 다시 성과로 연다.
- 발견한 요원·패치와 슬롯은 다시 잠그지 않으므로 첫 버전의 해금 학습을 반복시키지 않는다.
- 버전 업데이트로 패치노트 1개를 받고, 기존 규칙대로 패치노트 1개를 소비해 `레거시
  빌드 캐시` 영구 보너스를 살 수 있다. Product V2에서는 새 영구 성장 종류를 추가하지
  않고 기존 1레벨 범위만 검증한다.
- 업데이트 전 남은 비트, 요원 레벨과 장착 상태는 확인창에서 잃는 항목으로 정확히
  보여주며 업데이트는 자동으로 실행하지 않는다.

## 8. 화면 책임

| 화면 | 표시할 핵심 정보 | 하지 않을 일 |
|---|---|---|
| `DAY_PREP` | 방치 수입, 최대 네 요원, 강화, 패치 전후 비교, 해금 조건·진행도, 보고서, 다음 야간, 버전 업데이트 | 실시간 전투를 뒤에서 계속하지 않는다. |
| `NIGHT_ACTIVE` | 서버 안정도, 10칸 진행표와 다음 적, 별 경계, 적 HP, 별도 시간 표시, 요원 상태, 침입·피격 피드백, 조건부 1×/2× | 강화·패치·버전 탭과 중간 선택창을 함께 펼치지 않는다. |
| `SHIFT_RESULT` | 완료 웨이브, 별, 반복 급여, 최초 보상, 해금 요약, 실패 근거, 요원 보고, 다음 행동 | 보상을 다시 지급하거나 전투를 계속 진행하지 않는다. |
| `SETTINGS` | 실제 값과 일치하는 음량, 접근성 효과, 재시작·초기화 도구 | 모달 뒤 야간 전투를 진행하지 않는다. |

현재의 큰 `MainView`에 주야간 조건을 계속 추가하지 않는다. 본편 승격 시 주간, 야간과 결과
화면을 분리하고 `AppRoot`가 화면 전환과 수명주기를 소유한다.

## 9. 도메인·저장 경계

### 상태 흐름

```text
DAY_PREP
  → NIGHT_ACTIVE
  → SHIFT_RESULT
  → DAY_PREP
  → 필요 시 VERSION_UPDATE
```

- 전투 시간, 적, 서버 안정도, 요원과 보스 상태는 렌더러가 아니라 결정론적 도메인이 소유한다.
- 표시 계층은 도메인 사건을 애니메이션으로 재생하고 상태를 직접 변경하지 않는다.
- 결과 정산은 별 기록, 최초 보상 플래그, 비트 지급, 결과 생성과 `SHIFT_RESULT` 전환을
  한 번에 처리한다.

### Product V2 저장 항목

- 현재 phase
- 현재 버전과 버전 안의 야간근무 번호
- 현재 웨이브, 전투 하위 상태, 남은 시간과 선택한 배속
- 서버 안정도
- 진행 중인 적, 보스와 요원 상태
- 근무 성공·실패와 실패 근거
- 버전+근무별 최고 별과 이미 수령한 최초 보상
- 완료 웨이브 이정표, 요원·패치·슬롯·근무·재도전 배속 해금
- 비트, 패치노트, 요원, 패치와 영구 성장
- 주간 오프라인 수입 기준 시각
- 마지막 읽기 전용 근무 결과

### 오프라인 처리

- `DAY_PREP`: 최대 상한까지 예측 가능한 비트만 지급한다.
- `NIGHT_ACTIVE`: 전투를 진행하지 않고 저장한 정확한 상태에서 재개한다.
- `SHIFT_RESULT`: 보상을 다시 계산하거나 지급하지 않는다.
- 오프라인 결과는 한 번만 적용하고 저장한 뒤 읽기 전용 보고서를 표시한다.

Product V2 본편 승격에는 schema 3가 필요하다. 기존 schema 1·2는 메타 재화, 요원, 발견
패치와 영구 성장을 보존해 `DAY_PREP`로 원자적으로 전환하는 것을 기본으로 한다. 진행 중인
기존 전투를 억지로 야간 중간 상태로 변환하지 않는다.

   처리시간으로 정의하고 전멸 뒤 0.4초 자동 진행을 채택했다.
2. **실패 이유를 미리 읽고 결과를 즉시 이해해야 한다.** 다음 웨이브 특성, 별 경계,
