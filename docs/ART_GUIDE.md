# Pixel Night Shift 아트 가이드

## 방향

`Pixel Night Shift`의 화면은 **자정의 서버 운영실을 작은 픽셀 단말기로 들여다보는 느낌**을 목표로 합니다. 모든 에셋은 이 프로젝트를 위해 새로 설계하며, 참고 작품의 캐릭터·실루엣·팔레트·UI 구도를 재현하지 않습니다.

- 논리 해상도: `360x640`
- 픽셀 배율: 정수 배율만 사용하며, 텍스처 필터는 `Nearest`를 사용합니다.
- 원본 크기: UI 아이콘 `16x16`, 패치 `24x24`, 요원·일반 적 `32x32`, 보스 `48x48`
- 공통 앵커: 캐릭터와 적은 하단 중앙을 기준으로 배치합니다.
- 표현 방식: 안티앨리어싱과 반투명 가장자리 없이 단단한 픽셀 덩어리로 표현합니다.
- 배경: 전경 정보보다 어둡고 낮은 대비를 유지합니다.

## 시각 언어

색은 장식이 아니라 현재 상태를 읽게 하는 신호입니다.

| 의미 | 대표색 | 용도 |
|---|---|---|
| 정상·정보 | 청록 `#31D2C9` | 자동 전투, 진단, 비트 |
| 완료·안전 | 초록 `#6EE7A2` | 성공, 안전 패치, 확인 |
| 주의·정비 | 호박 `#FFB34D` | 유지보수, 비용, 경고 |
| 오류·보스 | 적색 `#DF4D67` | 적, 위험, 보스 특수 행동 |
| 영구·특수 | 보라 `#8A78E6` | 패치노트, 롤백, 장기 보너스 |
| 화면 바탕 | 남청 `#050914` | 운영실의 자정 분위기 |

한 에셋 안에서는 투명색을 포함해 12색 이하를 기본으로 합니다. 배경은 16색 이하로 제한합니다. 실루엣과 명암을 먼저 읽을 수 있어야 하며, 색상만으로 상태를 구분하지 않습니다.

### UI 표면 팔레트

위 표의 색은 픽셀 에셋 내부의 제한 팔레트입니다. UI는 한국어 가독성과 작은 화면 대비를 위해 다음 표면 토큰을 사용합니다. 에셋 청록 `#31D2C9`와 UI 선택 청록 `#52D6C8`은 서로 다른 역할이므로 임의로 섞지 않습니다.

| 역할 | 색상 |
|---|---|
| 깊은 삽화 배경 | `#050914` |
| 앱 바탕 | `#10151F` |
| 기본 패널 | `#182232` |
| 돌출 패널 | `#213047` |
| 테두리 | `#40526C` |
| 본문 | `#EDF4FF` |
| 보조 본문 | `#9DAFC7` |
| 정보·선택 | `#52D6C8` |
| 완료·안전 | `#7BE495` |
| 주의·비용 | `#F4C95D` |
| 오류·위험 | `#FF6B72` |
| 영구·특수 | `#8A78E6` |

새 화면은 각자 색 상수를 복제하지 않고 하나의 공통 UI 테마 소유자를 사용합니다. 현장은 `4px` 간격의 정보 밀도를 유지하고, 야간 운영실과 설명 화면은 `8~12px` 간격과 더 큰 중심 삽화를 사용해 역할을 구분합니다.

## 에셋 식별 규칙

### 요원

- `debugger`: 가로형 청록 바이저와 탐침. 안정적인 기술 담당자의 직선 실루엣.
- `build_engineer`: 호박색 작업 헬멧과 무거운 공구. 넓고 단단한 실루엣.
- `sprite_artist`: 비대칭 자홍 베레와 청록 스타일러스. 창작 도구가 분명한 실루엣.
- `qa_imp`: 작은 뿔과 체크리스트. 낮고 민첩한 품질 점검자 실루엣.

### 적

- `broken_pixel`: 깨진 덩어리와 흰 균열.
- `infinite_loop`: 서로 물고 도는 두 흐름과 정지된 중심 코어.
- `missing_resource`: 일부가 비어 있는 리소스 상자.
- `maintenance_error`: 작업모와 경고 줄무늬를 가진 정비 오류 드론.
- `watchdog_process`: 감시용 렌즈가 달린 대형 서버 감시 장치. 일반 적보다 1.5배 큰 `48x48` 실루엣.

### 패치

패치 아이콘은 장점과 부작용을 한눈에 떠올릴 수 있는 한 가지 기호만 사용합니다. 작은 글자나 숫자는 넣지 않습니다.

- `frame_skip`: 겹친 프레임과 전진 화살표
- `unsafe_build`: 경고 삼각형
- `reward_bypass`: 우회 경로와 보상 토큰
- `rollback_lock`: 되감기 화살표와 잠금장치
- `safe_mode`: 보호 방패와 확인 표시

## 배치 및 리사이즈

- 요원·적 스프라이트는 원본 비율을 유지하고 `TextureRect`의 `STRETCH_KEEP_ASPECT_CENTERED` 또는 같은 결과를 내는 설정을 사용합니다.
- 32픽셀 에셋은 화면에서 32, 64, 96픽셀처럼 정수 배율로만 확대합니다.
- 요원과 적의 발 위치는 원본 캔버스 하단에서 2~3픽셀 위로 통일합니다.
- 아이콘 주위에는 최소 1픽셀의 투명 여백을 남깁니다.
- 서버실 배경은 `344x64`이며 전투 패널 내부에서 자르지 않고 그대로 사용합니다.

## 재생성과 검증

PNG는 `tools/generate_pixel_assets.gd`가 Godot `Image` API만 사용해 생성합니다. 외부 이미지, 폰트, 플러그인, 네트워크 호출을 사용하지 않습니다. 같은 생성기 버전과 시드는 항상 같은 PNG를 만들어야 합니다.

```powershell
& "C:\path\to\Godot_v4.7-stable_win64_console.exe" --headless --path . --script res://tools/generate_pixel_assets.gd
& "C:\path\to\Godot_v4.7-stable_win64_console.exe" --headless --path . --script res://tools/validate_pixel_assets.gd
```

검증기는 다음을 확인합니다.

- 필수 파일 23개의 존재와 정확한 원본 크기
- `game/assets/manifest.json`의 SHA-256과 실제 PNG의 일치
- 투명 배경과 완전 불투명 픽셀만 사용하는지 여부
- 작은 픽셀 에셋에 맞는 제한 팔레트

생성 파일을 수동 수정하면 매니페스트 해시가 달라져 검증이 실패합니다. 수정이 필요하면 생성기를 변경하고 전체를 다시 생성합니다.

## 오프닝 배경 예외

타이틀과 프롤로그의 큰 배경은 소형 전투 에셋 생성기와 분리해 `game/assets/opening/`에서 관리합니다. 프로젝트 전용 image generation 결과를 `.godot/opening-art-sources/`에 임시 보관하고, `tools/prepare_opening_art.gd`가 정확한 화면 크기·16색 팔레트·2배 최근접 픽셀 그리드로 정리합니다.

- `title_background.png`: `360×640`, 시각 그리드 `180×320`
- `city_network.png`: `344×224`, 시각 그리드 `172×112`
- 생성 프롬프트, 도구, 출처와 최종 SHA-256은 `game/assets/opening/opening_art_manifest.json`에 기록합니다.
- 큰 원본은 런타임과 Git에 넣지 않습니다.

## 라이선스와 출처

모든 생성 PNG는 프로젝트 전용 오리지널 에셋이며 매니페스트에 `LicenseRef-PixelNightShift-Original`로 기록합니다. 생성기, 시드, 크기, SHA-256을 함께 기록해 출처가 섞이지 않도록 합니다.

## 캐릭터 애니메이션 예외

요원·적·보스의 애니메이션은 기존 정적 생성기를 덮어쓰지 않고 `game/assets/generated/sprites/<asset-id>/`의 `sprite-gen` component-row run으로 별도 생성합니다. 활성화 전까지 기존 PNG와 생성기는 롤백 자료로 보존합니다. 숫자 계약, Base Lock, row 재생성, 큐레이션과 Godot 매니페스트 연동 절차는 [SPRITE_PIPELINE.md](SPRITE_PIPELINE.md)를 따릅니다.
