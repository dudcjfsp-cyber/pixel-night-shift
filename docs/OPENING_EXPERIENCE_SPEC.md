# 오프닝 경험 명세

## 문서 상태

- 상태: 구현 대상
- 대상: 콜드 부트 타이틀, 첫 근무 프롤로그, 타이틀 음악
- 기준 해상도: 세로 `360×640`
- 비대상: 실제 계정·네트워크·클라우드 저장, 웹 내보내기 프리셋

이 문서는 [앱 셸 명세](APP_SHELL_SPEC.md)의 첫 설치 및 정상 완전 재실행 경로를 갱신합니다. 저장 복구, 오프라인 진행, 현장 온보딩과 Android 수명주기 계약은 기존 명세를 유지합니다.

## 제품 결정

1. 저장 상태가 정상이면 모든 콜드 부트에서 타이틀을 표시합니다.
2. 저장 이상은 타이틀로 숨기지 않고 기존 `SAVE_RECOVERY`로 바로 보냅니다.
3. 불러온 세션은 `이어하기` 전까지 활성 세션이 아닙니다. 타이틀 대기 중에는 전투, 주기 저장, 오프라인 집계를 시작하지 않습니다.
4. 새 근무는 `게임 시작` 뒤 5단계 프롤로그를 거쳐 최초 저장에 성공한 다음 현장으로 들어갑니다.
5. 프롤로그는 세계와 플레이어의 역할만 설명합니다. 기존 플레이형 온보딩은 조작과 판단 방법만 설명합니다.
6. `계정 연동 · 준비 중` 버튼은 향후 위치를 보여 주되 비활성 상태이며 어떤 네트워크 요청도 만들지 않습니다.
7. 타이틀 음악은 첫 실제 클릭·터치에서 활성화하고 프롤로그까지 이어집니다. 세션 진입 뒤에는 기존 전투 상태 음악으로 전환합니다.

## 실행 경로

```text
첫 설치
BOOT → TITLE(게임 시작) → PROLOGUE → 최초 저장 → GAMEPLAY + ONBOARDING

정상 완전 재실행
BOOT → TITLE(이어하기) → 세션 활성화 → 오프라인 진행 적용·저장
     → OPERATIONS_ROOM (+ 필요한 경우 OFFLINE_REPORT)

저장 이상
BOOT → SAVE_RECOVERY

프롤로그 중 뒤로 가기
PROLOGUE → TITLE
```

`AppRoot`는 활성 `GameSession`을 계속 하나만 소유합니다. 저장에서 검증한 후보는 타이틀 동안 별도 pending 값으로만 보관하고, `이어하기`에서 활성화합니다. 이 경계는 타이틀 대기 중 자동 전투와 저장 시각 오염을 막습니다.

## 타이틀 화면

### 정보 구조

```text
┌──────────────────────────────────┐
│ PIXEL NIGHT SHIFT          [설정] │
│ 픽셀 야간근무                     │
│                                  │
│      [자정의 서버 운영실 배경]     │
│                                  │
│        야간 운영 권한 대기 중      │
│        [ 게임 시작 / 이어하기 ]    │
│        [ 계정 연동 · 준비 중 ]     │
│   진행은 이 기기의 근무 기록에 저장 │
└──────────────────────────────────┘
```

- 배경은 풀스크린 `TextureRect`로 표시하고 버튼 영역에는 반투명하지 않은 저대비 패널을 둡니다.
- 버튼과 로고는 이미지에 굽지 않고 Godot UI로 그립니다.
- 저장 없음: 주 행동 `게임 시작`, 상태 문구 `첫 야간근무를 준비합니다.`
- 저장 있음: 주 행동 `이어하기`, 상태 문구 `저장된 야간근무가 대기 중입니다.`
- 저장 있음: 보조 행동 `오프닝 다시 보기`는 세션을 활성화하지 않고 프롤로그를 재생한 뒤 타이틀로 돌아옵니다.
- 설정은 세션 없이도 열 수 있습니다.
- 계정 연동 버튼은 비활성 상태와 `임시 테스트에서는 기기 저장을 사용합니다.` 안내를 함께 표시합니다.

### 배경 미술 계약

- 최종 크기: `360×640` PNG, 완전 불투명
- 시각 그리드: `180×320`로 읽히는 굵은 픽셀 덩어리
- 장면: 비어 있는 중앙 관제석을 뒤에서 바라보는 자정의 서버 운영실
- 좌우 서버 랙이 화면 프레임을 만들고 중앙 콘솔은 권한 인계를 암시합니다.
- 중경의 네 요원은 각 단말에서 자동 대응하며 일부 서버에만 붉은 오류광이 켜집니다.
- 상단과 하단은 UI를 위해 낮은 대비와 적은 디테일을 유지합니다.
- 중심색: `#050914`, `#101E2F`, `#183247`
- 강조색: `#31D2C9`, `#FFB34D`, `#DF4D67`, `#8A78E6`
- 금지: 이미지 내 문자·로고·워터마크, 전면 캐릭터 단체 포즈, 참고 IP의 실루엣·팔레트·구도 재현

## 프롤로그

프롤로그는 사용자가 직접 넘기는 5단계 카드이며 언제든 건너뛸 수 있습니다. 각 단계는 한 문장 중심으로 읽히고, 마지막 단계의 주 행동만 `근무 인계받기`로 표시합니다.

새 근무에서 완료하거나 건너뛰면 최초 저장으로 이어집니다. 기존 근무에서 다시 보는 경우에는 완료하거나 건너뛰면 저장·오프라인 집계 없이 타이틀로 돌아옵니다.

| 단계 | 제목 | 본문 | 시각 구성 |
|---|---|---|---|
| 1 | 꺼지지 않는 도시 | 도시가 잠든 뒤에도 서비스는 멈추지 않습니다. | 신규 네트워크 야경 |
| 2 | 깨어난 결함 | 누적된 결함은 깨진 픽셀과 비정상 프로세스로 깨어납니다. | 서버실 배경 + 기존 적 |
| 3 | 자동 대응 | 요원들은 지시를 기다리지 않고 현장을 지킵니다. | 서버실 배경 + 기존 네 요원 |
| 4 | 자동화의 한계 | 하지만 병목의 원인과 감수할 위험까지 결정하지는 못합니다. | 진단·정비·패치 신호 |
| 5 | 권한 인계 | 03:00, 야간 운영 권한이 당신에게 이관됩니다. 진단하고, 강화하고, 패치를 승인하십시오. | 타이틀 중앙 관제석 재사용 |

신규 프롤로그 배경은 `344×224` PNG 한 장만 추가합니다. 나머지 단계는 기존 전장 배경, 요원·적 스프라이트와 UI 아이콘을 정수 배율로 재조합합니다. `동작 줄이기` 설정에서는 반복 애니메이션을 멈춥니다.

## 오디오

### 타이틀 루프

- 파일: `title_loop.wav`
- 길이: 16마디, 4/4, 72 BPM, 약 53.333초
- 조성: E minor
- 형식: 22,050 Hz, mono, PCM16 WAV, 반복 재생
- 성격: 반속 느낌의 낮은 triangle/pulse bass, 드문 아르페지오와 단말기 tick
- 피함: 전투형 리드, 강한 킥·스네어, 지속적인 고역 자극

### 권한 승인음

- 파일: `shift_authorized.wav`
- 길이: 약 0.95초
- 구성: E4–G4–B4–E5 상승 동기와 낮은 단말기 handshake
- 타이틀의 첫 주 행동에서 재생하며 음악과 함께 프롤로그 전환을 가립니다.

두 파일은 외부 녹음·샘플·멜로디를 사용하지 않는 프로젝트 원본 결정론적 합성물로 만들고 오디오 manifest와 출처 문서를 갱신합니다.

## 수용 기준

- 저장 없음과 저장 있음 모두 타이틀로 진입하며 주 버튼 문구가 다릅니다.
- 타이틀과 프롤로그 동안 활성 세션 ID는 `0`이고 전투·주기 저장이 발생하지 않습니다.
- 새 근무는 프롤로그 완료 또는 건너뛰기 뒤 최초 저장 성공 시에만 활성화됩니다.
- 기존 근무는 `이어하기` 뒤에만 활성화되고 오프라인 진행은 한 번만 적용·저장됩니다.
- 프롤로그 5단계, 건너뛰기, 뒤로 가기, 기존 현장 온보딩이 서로 역할을 침범하지 않습니다.
- 모든 버튼은 최소 `48×48`, 주 버튼은 최소 높이 `52px`를 유지합니다.
- headless 앱 셸 테스트와 프로젝트 부팅이 통과합니다.
